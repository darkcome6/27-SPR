# 5.3 舵轮的运动学解算

> **一句话本质：舵轮 = 每个轮子都能"先转向，再定快慢"。**
> 所以解算要做两件事：**算出每个轮子的朝向角 δ，和它的速度大小 |v|**。

---

## 一、先看结构

一个舵轮模块 = **两个电机**：

| 电机 | 干什么 | 用什么闭环 |
|---|---|---|
| **转向电机** | 把轮子转到指定朝向 δ | 位置环（角度环） |
| **驱动电机** | 让轮子以指定速度转 | 速度环 |

四舵轮底盘，等价于"四个可以任意朝向的轮子"——理论上**没有它走不了的方向**（真正的全向），代价是结构复杂、控制要求高。

### 坐标系和轮子编号（动手前先统一，不然符号全错）

| 量 | 约定 |
|---|---|
| `x` | 车头朝前为正 |
| `y` | **车体向右为正** |
| `ω` | **俯视逆时针（左转）为正** |

轮心坐标记作 `(x_i, y_i)`（相对车体中心），编号和 5.2 一致：**0 前左、1 前右、2 后右、3 后左**。

> ⚠️ **5.1（麦轮）用的是 `y` 向左为正**，本节和 5.2 用 `y` 向右为正（跟实车代码一致）。
> 两边对照时记得换号：`vy(向右) = −vy(向左)`。

---

## 二、反解：车体速度 → 每个轮子的"朝向 + 速度"

**第一步：算轮心处的速度。**

车体既在平移、又在自转时，轮心处的合速度是（`y` 向右为正、`ω` 俯视逆时针为正）：

$$
\begin{aligned}
v_{i,x} &= v_x + \omega\, y_i\\
v_{i,y} &= v_y - \omega\, x_i
\end{aligned}
$$

**这两项要能讲出来**：
- `(v_x, v_y)`：车体自己的平移，每个轮子都一样。
- `ω·(y_i, −x_i)`：**自转带来的切向速度**。轮子离中心越远，自转时被"甩"得越快。

**第二步：舵轮只要"大小 + 方向"。**

$$
\delta_i = \operatorname{atan2}(v_{i,y},\ v_{i,x}),
\qquad
|v_i| = \sqrt{v_{i,x}^2 + v_{i,y}^2}
$$

`atan2` 会自动处理四个象限和正负号——**这一步不要自己用 `atan` 加判断，容易出错**。

```c
void Swerve_Solve(float vx, float vy, float w, Swerve_t *mod, uint8_t n)
{
    for (uint8_t i = 0; i < n; i++) {
        float vix = vx + w * mod[i].y;          /* 轮心速度：平移 + 自转 */
        float viy = vy - w * mod[i].x;

        float target_angle = atan2f(viy, vix);  /* 该轮应该朝向哪里 */
        float speed        = sqrtf(vix*vix + viy*viy);

        Swerve_SetModule(&mod[i], target_angle, speed);   /* 交给转向+驱动两个闭环 */
    }
}
```

> 这段是**通用写法**：换个布局、加个轮子，代码一个字都不用改，只改 `mod[i].x / .y`。
> 只在四个角布局时，`w * mod[i].y` 就是 `±a`，可以像实车代码那样直接展开成四项。

### 实车布局：四个轮子在四个角（45°）

实车轮心在 `(x_i, y_i) = (±l/√2, ±l/√2)`（`l` = 轮心到车心距离）。
代入上面两式，每个轮子的自转项正好是 `±(√2/2)·l·ω`，记 `a = (√2/2)·l·ω`：

| 轮 | 位置 | 轮心速度矢量 `(v_{i,x}, v_{i,y})` |
|---|---|---|
| 0 | 前左 | `(v_x − a, v_y − a)` |
| 1 | 前右 | `(v_x + a, v_y − a)` |
| 2 | 后右 | `(v_x + a, v_y + a)` |
| 3 | 后左 | `(v_x − a, v_y + a)` |

**一句话记住**：**把平移矢量 `(v_x, v_y)` 原样发给四个轮子，再按"它所在的那个角"各加一个 45° 的对角矢量 `(±a, ±a)`。**

> **和 5.2 的关系（很值得对照一下）**：5.2 也是四个轮子装在 45° 的四个角上 —— **布局一样，差别只在于"轮子能不能转方向"**：
> - **5.2 全向轮**：驱动方向**固定**（只能沿切向出力）→ 必须把轮心速度**投影**到那个固定方向上；
> - **5.3 舵轮**：驱动方向**能转** → 轮子直接朝着 `V_i` 的方向就行，**不用投影**。
>
> 所以两节的数字长得不完全一样，**但物理图景是同一个**：先把"车想怎么走"变成"每个轮心该怎么动"，再让轮子去配合它。

速度大小：

$$
\begin{aligned}
|v_0| &= \sqrt{(v_x - a)^2 + (v_y - a)^2}, & |v_1| &= \sqrt{(v_x + a)^2 + (v_y - a)^2}\\
|v_2| &= \sqrt{(v_x + a)^2 + (v_y + a)^2}, & |v_3| &= \sqrt{(v_x - a)^2 + (v_y + a)^2}
\end{aligned}
$$

朝向（就是上面同一个矢量的 `atan2`）：

$$
\begin{aligned}
\delta_0 &= \operatorname{atan2}(v_y - a,\ v_x - a), & \delta_1 &= \operatorname{atan2}(v_y - a,\ v_x + a)\\
\delta_2 &= \operatorname{atan2}(v_y + a,\ v_x + a), & \delta_3 &= \operatorname{atan2}(v_y + a,\ v_x - a)
\end{aligned}
$$

> **为什么四个式子长得一模一样、只是符号不同？**
> 因为四个轮子都在 45° 线上：`(±l/√2, ±l/√2)`。所以自转项永远是"两个分量等大"的。
> 这是四角布局特有的；换成三轮 120°，四个式子就不会这么整齐了。

### 对照实车代码

**① 速度**（原文第 5 页）：

```c
static void chassis_vector_to_M3508_wheel_speed(fp32 vx_set, fp32 vy_set, fp32 wz_set,
                                                fp32 wheel_speed[4], int8_t need_flip[4])
{
    wheel_speed[0] = sqrt(pow(vy_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2)
                        + pow(vx_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2));
    wheel_speed[1] = sqrt(pow(vy_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2)
                        + pow(vx_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2));
    wheel_speed[2] = sqrt(pow(vy_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2)
                        + pow(vx_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2));
    wheel_speed[3] = sqrt(pow(vy_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2)
                        + pow(vx_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2, 2));
}
```

**② 朝向**（原文第 4 页）：

```c
void chassis_vector_to_mecanum_wheel_angle(fp32 vx_set, fp32 vy_set, fp32 wz_set,
                                           fp32 wheel_angle[4], int8_t need_flip[4])
{
    if (!(vx_set == 0 && vy_set == 0 && wz_set == 0))   /* 三速全零就不用算了 */
    {
        wheel_angle[0] = atan2((vy_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2),
                               (vx_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2));
        wheel_angle[1] = atan2((vy_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2),
                               (vx_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2));
        wheel_angle[2] = atan2((vy_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2),
                               (vx_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2));
        wheel_angle[3] = atan2((vy_set + wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2),
                               (vx_set - wz_set * MOTOR_DISTANCE_TO_CENTER * SQRT2));
    }
}
```

看这两段代码时，有三点最容易卡住：

1. **`MOTOR_DISTANCE_TO_CENTER * SQRT2` 就是公式里的 `a`** —— 常数被合并进宏了。
   它跟你的机械尺寸有关，**别照抄数字**。
2. **`wheel_speed` 给的是"线速度（模长）"**，不是电机转速。要换成电机转速，还得除以轮子半径、乘上减速比。
3. **函数名里写着 `mecanum`，但算的是舵轮的朝向角** —— 这份代码和麦轮同源，别被名字骗了。
   参数表里的 `need_flip[4]` 也不能忽略：**它就是第三节的"最短路径"用的** —— 谁需要把朝向翻 180°、驱动速度取反，谁就置位。

> ⚠️ 实车代码里 `vy_set` 用的就是"**向右为正**"：把符号代进去，和上面四式逐项吻合。
> 这就是本节开头坚持用 `y` 向右为正的原因 —— **不这么定，公式和实车代码就对不上。**

### 公式自查法（30 秒就能做）

代几组特殊值，看结果"讲不讲得通"：

| 输入 | 应该看到什么 |
|---|---|
| `vx=1, vy=0, ω=0` | 四个轮子**全都朝 0°（正前方）**，大小都是 1 |
| `vx=0, vy=1, ω=0` | 四个轮子**全都朝 90°（正右方）**，大小都是 1 |
| `vx=1, vy=1, ω=0` | 四个轮子**全都朝 45°（右前方）**，大小都是 `√2` |
| `vx=0, vy=0, ω=1` | 四个轮子速度大小**都是 `a√2 = lω`**（正好等于"轮心绕车心转"的线速度），朝向分别是：前左→左后、前右→左前、后右→右前、后左→右后 |

最后一行的**朝向**最好动手推一遍：纯自转时，每个轮子都必须垂直于"它到车心的连线"，四轮合成起来才是原地打转。

## 三、真正的工程细节：最短路径转向（必须做）

如果直接让转向电机从当前角转到 `δ_i`，会出现这种蠢事：

```
当前朝向 0°，目标朝向 179°
直接转：0° → 179°，转向电机要转 179° ！！！
正确做法：把目标角翻成 -1°（179° − 180°），
          同时把驱动速度取负 —— 转向电机只走 1°，效果一模一样
```

**规则：如果目标角与当前角的差超过 90°，就把目标角加 180°，驱动速度取反。**

因为"轮子朝反方向、反向转"和"朝向正方向、正向转"产生的**运动完全相同**——但后者少走一大圈。

```c
/* 最短路径优化：轮子可正反转，所以朝向差超过 90° 时"反向抄近路" */
float diff = Angle_Normalize(target_angle - mod->now_angle);   /* 归一到 (-180°, 180°] */
if (fabsf(diff) > PI / 2.0f) {
    target_angle = Angle_Normalize(target_angle + PI);         /* 朝向翻 180° */
    speed = -speed;                                            /* 速度取反 */
}
```

**为什么可以这么干？** 舵轮的驱动电机本来就能正反转。这个技巧让转向电机永远只走 ≤ 90°——**响应更快、寿命更长、也不会在高速旋转时"转不过来"**。

## 四、角度归一化（不做一定出 bug）

电机角度会一直累加（比如 720°、-1080°），而"最短路径""取差值"这些操作必须在 `(-180°, 180°]` 里做：

```c
float Angle_Normalize(float rad)
{
    while (rad >  PI) rad -= 2.0f * PI;
    while (rad <= -PI) rad += 2.0f * PI;
    return rad;
}
```

> 注意区分两种角：
> - **对外接口/计算**：用归一化角（-180°~180°），避免数值越来越大
> - **转向电机的目标**：应该基于**当前实际角**给"连续角"（`now + 最短差值`），否则电机可能为了从 350° 到 10° 反向绕一大圈
> 这是舵轮调试中最容易踩的坑之一。

## 五、上电之前必须做的标定

| 项目 | 为什么 |
|---|---|
| **转向零位** | 每个模块的绝对零位不同（编码器零点 / 机械安装误差）→ 上电时读到"零位偏移表" |
| **转向正方向** | 电机角度增大 = 逆时针（俯视）？还是顺时针？**必须实测** |
| **驱动正方向** | 轮子正转 = 车速向前？ |
| **模块位置 `(x_i, y_i)`** | 量错 → 自转时车"画圈"而不是原地转 |

**标定方法**：手动把某个模块转到与车体纵轴平行，读编码器角度，存成零位；四个模块各做一次。
零位必须**存 Flash**（掉电不丢，见 2.3.3）——不然每次上电都得重新标。

## 六、常见坑

1. **坐标系/正方向没统一** → 公式和实车代码对不上，车只会往反方向跑，而且怎么调 PID 都没用。
   **动手前先把 x / y / ω 的正方向写进代码文件头注释**（`y` 到底朝左还是朝右，这一条最容易出错）。
2. **没做最短路径转向** → 原地抽搐、转向电机发热、高速时"转不过来"。
3. **角度没有归一化** → 电机目标角越来越大，最后跑飞或溢出。
4. **把"归一化角"直接当电机目标** → 从 179° 到 -179° 时电机反向绕 358°。
5. **转向环、驱动环都做成位置环** → 驱动电机要的是**速度环**（速度环内层还能再串电流环）。
6. **自转时没限制 ω** → 舵轮来不及转到目标角，轮子"斜着蹭地" → 打滑、磨损、定位漂移。
7. **四个模块零位不一致** → 车永远走不直（而且不是 PID 的问题，怎么调都调不好）。
8. **忘了限幅**：`|v_i|` 超过轮子最大线速度时要整体缩放（同 5.1 第八节）。

## 七、舵轮 vs 麦轮：什么时候用什么

| | 麦轮 | 舵轮 |
|---|---|---|
| 机械复杂度 | 低 | 高（4 组转向 + 4 组驱动） |
| 打滑 | 明显（辊子天生打滑） | 少（普通橡胶轮） |
| 越障/负载 | 一般 | 好 |
| 定位精度 | 差 | 好 |
| 控制难度 | 低 | 高（要标零位、要做最短路径） |

**一句话**：麦轮"便宜好上手但打滑"；舵轮"贵且难调，但又准又有劲"。
