# 5.3 舵轮的运动学解算

> **一句话本质：舵轮 = 每个轮子都能"先转向，再定快慢"。**
> 所以解算要做两件事：**算出每个轮子的朝向角 δ，和它的速度大小 |v|**。

---

## 一、先看结构

一个舵轮模块 = **两个电机**：

| 电机 | 干什么 | 用什么闭环 |
|---|---|---|
| **转向电机** | 把轮子转到指定朝向 δ | 位置环（角度环） |
| **驱动电机** | 让轮子以指定速度转 | 速度环 |

四舵轮底盘，等价于"四个可以任意朝向的轮子"——理论上**没有它走不了的方向**（真正的全向），代价是结构复杂、控制要求高。

---

## 二、反解：车体速度 → 每个轮子的"朝向 + 速度"

**第一步：算轮心处的速度。**

轮子 i 的安装位置是 `(x_i, y_i)`（相对车体中心，x 前 y 左）。车体既在平移又在自转时，轮心处的合速度是：

$$
\begin{aligned}
v_{i,x} &= v_x - \omega\, y_i\\
v_{i,y} &= v_y + \omega\, x_i
\end{aligned}
$$

**这两项要能讲出来**：
- `v_x, v_y`：车体自己的平移，每个轮子都一样。
- `ω·x_i`、`-ω·y_i`：**自转带来的切向速度**。轮子离中心越远，自转时被"甩"得越快。

**第二步：从合速度得到朝向和大小。**

$$
\delta_i = \operatorname{atan2}(v_{i,y},\ v_{i,x}),
\qquad
|v_i| = \sqrt{v_{i,x}^2 + v_{i,y}^2}
$$

`atan2` 会自动处理四个象限和正负号——**这一步不要自己用 `atan` 加判断，容易出错**。

```c
void Swerve_Solve(float vx, float vy, float w, Swerve_t *mod, uint8_t n)
{
    for (uint8_t i = 0; i < n; i++) {
        float vix = vx - w * mod[i].y;          /* 轮心速度：平移 + 自转 */
        float viy = vy + w * mod[i].x;

        float target_angle = atan2f(viy, vix);  /* 该轮应该朝向哪里 */
        float speed        = sqrtf(vix*vix + viy*viy);

        Swerve_SetModule(&mod[i], target_angle, speed);   /* 交给转向+驱动两个闭环 */
    }
}
```

## 三、真正的工程细节：最短路径转向（必须做）

如果直接让转向电机从当前角转到 `δ_i`，会出现这种蠢事：

```
当前朝向 175°，目标朝向 -170°（相当于 190°）
直接转：175° → -170°，要走 345° ！！！
正确做法：175° → 10°（反向 180°），同时把驱动速度取负 —— 只走 5°
```

**规则：如果目标角与当前角的差超过 90°，就把目标角加 180°，驱动速度取反。**

因为"轮子朝反方向、反向转"和"朝向正方向、正向转"产生的**运动完全相同**——但后者少走一大圈。

```c
/* 最短路径优化：轮子可正反转，所以朝向差超过 90° 时"反向抄近路" */
float diff = Angle_Normalize(target_angle - mod->now_angle);   /* 归一到 (-180°, 180°] */
if (fabsf(diff) > PI / 2.0f) {
    target_angle = Angle_Normalize(target_angle + PI);         /* 朝向翻 180° */
    speed = -speed;                                            /* 速度取反 */
}
```

**为什么可以这么干？** 舵轮的驱动电机本来就能正反转。这个技巧让转向电机永远只走 ≤ 90°——**响应更快、寿命更长、也不会在高速旋转时"转不过来"**。

## 四、角度归一化（不做一定出 bug）

电机角度会一直累加（比如 720°、-1080°），而"最短路径""取差值"这些操作必须在 `(-180°, 180°]` 里做：

```c
float Angle_Normalize(float rad)
{
    while (rad >  PI) rad -= 2.0f * PI;
    while (rad <= -PI) rad += 2.0f * PI;
    return rad;
}
```

> 注意区分两种角：
> - **对外接口/计算**：用归一化角（-180°~180°），避免数值越来越大
> - **转向电机的目标**：应该基于**当前实际角**给"连续角"（`now + 最短差值`），否则电机可能为了从 350° 到 10° 反向绕一大圈
> 这是舵轮调试中最容易踩的坑之一。

## 五、上电之前必须做的标定

| 项目 | 为什么 |
|---|---|
| **转向零位** | 每个模块的绝对零位不同（编码器零点 / 机械安装误差）→ 上电时读到"零位偏移表" |
| **转向正方向** | 电机角度增大 = 逆时针（俯视）？还是顺时针？**必须实测** |
| **驱动正方向** | 轮子正转 = 车速向前？ |
| **模块位置 `(x_i, y_i)`** | 量错 → 自转时车"画圈"而不是原地转 |

**标定方法**：手动把某个模块转到与车体纵轴平行，读编码器角度，存成零位；四个模块各做一次。
零位必须**存 Flash**（掉电不丢，见 2.3.3）——不然每次上电都得重新标。

## 六、常见坑

1. **没做最短路径转向** → 原地抽搐、转向电机发热、高速时"转不过来"。
2. **角度没有归一化** → 电机目标角越来越大，最后跑飞或溢出。
3. **把"归一化角"直接当电机目标** → 从 179° 到 -179° 时电机反向绕 358°。
4. **转向环、驱动环都是位置环** → 驱动电机要的是**速度环**（速度环内层还能再串电流环）。
5. **自转时没限制 ω** → 舵轮来不及转到目标角，轮子"斜着蹭地"→ 打滑、磨损、定位漂移。
6. **四个模块零位不一致** → 车永远走不直（而且不是 PID 的问题，怎么调都调不好）。
7. **忘了限幅**：`|v_i|` 超过轮子最大线速度时要整体缩放（同 5.1 第八节）。

## 七、舵轮 vs 麦轮：什么时候用什么

| | 麦轮 | 舵轮 |
|---|---|---|
| 机械复杂度 | 低 | 高（4 组转向 + 4 组驱动） |
| 打滑 | 明显（辊子天生打滑） | 少（普通橡胶轮） |
| 越障/负载 | 一般 | 好 |
| 定位精度 | 差 | 好 |
| 控制难度 | 低 | 高（要标零位、要做最短路径） |

**一句话**：麦轮"便宜好上手但打滑"；舵轮"贵且难调，但又准又有劲"。
