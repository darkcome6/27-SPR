# 5.6 前馈控制器

> **一句话本质：别等"错了再改"，而是"我已知它需要多少，就先把这部分给上"。**
> 反馈（PID）负责修**残余误差**，前馈负责提供**大头**。

---

## 一、反馈的天然缺陷

回忆 5.4 的 PID：它的输出**完全依赖误差**。

```
u = Kp·e + ...      其中 e = 目标 - 实际
```

这意味着：**没有误差 → 就没有输出**。
而电机要转起来必须要有输出 —— 于是系统总会"稳定地差一点点"（稳态误差），并且**永远滞后一拍**：扰动发生了 → 速度掉了 → 误差出现了 → 才开始补。

**前馈就是来干掉这个"赖账环节"的。**

---

## 二、结构：前馈 + 反馈并联

```
                      ┌───────── 前馈 ─────────┐
目标 ──┬──> [ Kf·目标 + Ka·目标加速度 ] ──────┤
       │                                       ├──> 电机
       └──> [ PID ] ──────────────────────────┤
                ↑ 实际                          │
```

$$
u = \underbrace{K_f\, v_{\text{目标}} + K_a\, a_{\text{目标}}}_{\text{前馈：已知的量}}
    + \underbrace{\text{PID}(e)}_{\text{反馈：只修残差}}
$$

**效果上的差别（关键）：**

| | 只有反馈 | 加了前馈 |
|---|---|---|
| 起步 | 先有误差，再补 → 慢半拍 | 立刻给上该有的输出 → **跟随误差骤降** |
| 稳态 | 靠 `Ki` 硬磨，或留一点稳态误差 | 前馈已经给够，PID 几乎不用出力 |
| `Kp` 可以取多大 | 必须够大才能压住误差 → 容易振荡 | **可以取小 → 系统更稳** |

**这就是"优化控制器"比"苦苦调参"更值钱的地方。**

---

## 三、怎么标定前馈系数（队里可操作的方法）

### ① 速度前馈 `Kf`：画一条"目标速度 → 所需输出"的曲线

1. 把速度环的 **PID 全部关掉**，改为**开环**：直接给电机一个固定的输出 `u`。
2. 记录电机稳定后的速度 `v`。换几个 `u`，得到一组数据。

| 输出 u | 稳态速度 v |
|---|---|
| 0.1 | 0.0（转不动：静摩擦） |
| 0.3 | 0.42 m/s |
| 0.5 | 0.95 m/s |
| 0.7 | 1.45 m/s |

3. 拟合一条直线 `v ≈ a·u + b`：

$$
K_f \approx \frac{1}{a} \quad(\text{斜率}), \qquad
u_{\text{摩擦}} \approx -\frac{b}{a}\ \text{的绝对值}\ (\text{截距})
$$

- **斜率**给出 `Kf`：稳态下"要跑 1 m/s 需要多少输出"。
- **截距**就是**库仑摩擦/死区**：输出小于它电机根本不转。这部分可以用"摩擦补偿"补上（见 5.7 的补充）。

### ② 加速度前馈 `Ka`：估转动惯量

`Ka` 的物理意义就是**等效惯量 J**（转矩 = J × 角加速度）。
可标定方式：给不同加速度的目标，看"跟随误差与加速度是否成比例"，比例系数就是 `Ka`。

**初学时可以先只做速度前馈**——它带来的收益最大，也最容易标定。

## 四、代码

```c
typedef struct {
    float kf;        /* 速度前馈系数：输出 / (m/s) */
    float ka;        /* 加速度前馈系数：输出 / (m/s²) */
    float kfric;     /* 静摩擦补偿（可选） */
    float v_last;    /* 上一拍目标速度，用来求目标加速度 */
} FF_t;

float FF_Calc(FF_t *f, float v_target, float dt)
{
    float a_target = (v_target - f->v_last) / dt;    /* 目标的加速度（已知量！） */
    f->v_last = v_target;

    float u = f->kf * v_target + f->ka * a_target;

    /* 静摩擦补偿：有速度意图时，额外给一点点，帮它"跨过死区" */
    if (fabsf(v_target) > 0.01f) {
        u += (v_target > 0.0f) ? f->kfric : -f->kfric;
    }
    return u;
}

/* 使用时：前馈 + 反馈 相加 */
float out = FF_Calc(&ff, target_vel, dt)
          + PID_Calc(&vel_pid, target_vel, actual_vel, dt);
```

**注意**：目标加速度是对**目标速度**求差分，所以它是"已知量"，不需要任何传感器——**这正是前馈便宜的来源**。
（要小心 `v_target` 有阶跃跳变时不加限幅，`a_target` 会瞬间巨大 → 输出饱和到顶。**给目标做斜坡限幅**。）

## 五、什么时候前馈特别有用

| 场景 | 前馈补偿什么 |
|---|---|
| 底盘直线高速行驶 | 摩擦、反电动势（速度越高越明显） |
| 云台 pitch 轴 | **重力矩**（→ 5.7 专讲） |
| 机械臂关节 | 重力 + 惯量 |
| 平衡车前进 | 目标倾角对应的期望加速度 |

**共同点：这些量都是"可以算出来/测出来"的，不是未知扰动。**
未知扰动交给反馈，已知的确定性项交给前馈。

---

## 六、常见坑

1. **前馈系数给太大** → 直接冲过头（前馈没有"自我收敛"能力，给多少就是多少）。
2. **标定时用了非稳态数据** → 拟合出来的 `Kf` 偏大。**必须等速度稳定后再取点。**
3. **目标速度阶跃不做斜坡** → 加速度前馈瞬间饱和，表现为"起步一顿"。
4. **忘了前馈也有输出限幅**：`u_ff` 和 `u_pid` 相加后要统一限幅（在输出端再做一次）。
5. **拿前馈去补"未知扰动"** → 补不了，只会让系统更乱。
