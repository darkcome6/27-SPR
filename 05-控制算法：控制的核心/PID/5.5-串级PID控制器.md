# 5.5 串级 PID 控制器（位置环 + 速度环）

> **一句话本质：外环（位置）的输出，就是内环（速度）的目标。**
> 内环负责"把速度跟准"，外环只负责"给出该有多快"——**扰动在还没影响到位置之前，就被内环吃掉了。**

---

## 一、为什么要串起来

先看单环（只有一个位置环）的问题：

```
目标位置 → [位置PID] → 输出直接给电机
              ↑实际位置
```

问题：**电机一遇到扰动（负载变大、电压下降、上坡），转速立刻掉，位置才慢慢偏。**
位置环要等到"位置已经错了"才开始纠正——**永远是滞后的**。

串级之后：

```
目标位置 → [位置PID] → 目标速度 → [速度PID] → 电流/PWM → 电机
              ↑实际位置                ↑实际速度(编码器)
```

- **内环（速度环）**：快。负载一变，速度立刻被拉回来,**扰动还没机会影响到位置**。
- **外环（位置环）**：慢。它只关心"还差多远"，输出一个"应该跑多快"。

**这就是串级 PID 的全部道理：把快的东西关在内层，把慢的目标交给外层。**

## 二、代码骨架

```c
typedef struct {
    PID_t pos;              /* 位置环 */
    PID_t vel;              /* 速度环 */
    float target_pos;       /* 目标位置（外部给） */
    float target_vel;       /* 位置环的输出 = 速度环的目标 */
    float max_vel;          /* 速度上限：位置环输出的限幅（= 内环最大目标速度） */
} Cascade_t;

void Cascade_Update(Cascade_t *c, float now_pos, float now_vel, float dt)
{
    /* ---- 外环：位置 → 目标速度 ---- */
    c->pos.out_max = c->max_vel;                     /* 关键：外环输出限幅 = 内环速度上限 */
    c->target_vel  = PID_Calc(&c->pos, c->target_pos, now_pos, dt);

    /* ---- 内环：目标速度 → 输出 ---- */
    c->vel.out_max = MOTOR_OUT_MAX;                  /* 内环输出限幅 = 电机/电流上限 */
    float out      = PID_Calc(&c->vel, c->target_vel, now_vel, dt);

    Motor_Set(out);
}
```

**两个限幅是这套结构的灵魂：**

| 限幅 | 作用 |
|---|---|
| **外环输出限幅 = `max_vel`** | 天然实现"限速"：不管差多远，最多也就跑 `max_vel`（保护机械、保护电机） |
| **内环输出限幅** | 限制电流/PWM，防止过流、过热、打坏齿轮 |

---

## 三、内环必须比外环"快"

这是串级能成立的前提：

$$
\text{内环带宽} \gtrsim 3 \sim 5 \times \text{外环带宽}
$$

怎么做到？

| 做法 | 说明 |
|---|---|
| **内环用更短的周期** | 例如速度环 1 ms、位置环 5 ms（或都 1 ms，但速度环参数更"猛"） |
| **内环参数调得更激进** | 速度环要"跟得住"外环给的目标 |
| **外环更保守** | 位置环 P 通常不需要很大 |

**如果内环太慢**：外环会以为"我给的指令没被执行"，于是拼命加大输出 → 振荡甚至发散，**而且怎么调外环都没用**。

---

## 四、调试顺序（顺序错了会浪费一整晚）

1. **先把内环单独调通**：直接给速度阶跃目标，看实际速度跟随情况（超调小、跟随快、稳态误差≈0）。
2. **再把位置环接上**：从很小的 `Kp` 开始加，直到定位又快又不超冲。
3. **位置环通常只需要 P**：因为稳态误差由内环已经保证（速度跟得准 → 位置自然到得了），不需要外环再积一分。
   如果确实需要，`Ki` 也要给得非常小。

> **反例（新手最常见）**：两边都开 PI + D，然后一起调。
> 结果：永远分不清是哪个环在抖，参数互相掩盖。**一次只调一个环。**

---

## 五、一个具体例子：底盘定距前进

```
目标：车往前走 1 m 后精确停下
```

| 层 | 目标 | 反馈 | 输出 |
|---|---|---|---|
| 位置环 | 1.0 m | 里程计累计位移 | 目标速度（限幅 ±1.5 m/s） |
| 速度环 | 目标速度 | 编码器测出的车体速度 | 四个轮子的 PWM |

好处立刻可见：

- 上坡时（扰动）→ 速度掉 → **速度环立刻补电压** → 位置环几乎感觉不到。
- 快到终点时 → 位置环自动把目标速度降下来 → **自然减速，不会冲过头**。
- 万一需要急停 → 把 `max_vel` 设成 0，整条链就没输出了。

---

## 六、常见坑

1. **内环带宽不够就接外环** → 外环永远调不好。**先确认内环能"指哪打哪"。**
2. **外环输出没限幅** → 目标速度给到几百 m/s，内环直接饱和、车冲出去（安全事故）。
3. **两个环都用 D** → 噪声被放大两遍，电机啸叫。
4. **内外环单位没对齐**：外环输出是 **m/s**，内环目标也必须按 **m/s** 解释（不能一边 m/s 一边 RPM）。
5. **内外环用同一个 PID 结构体** → 状态（积分、上次误差）互相污染，行为完全不可复现。
6. **采样周期不固定** → 内外环的"带宽比"随时变化，表现时好时坏。
