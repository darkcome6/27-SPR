# 5.8 坐标变换（旋转矩阵）：云台 ↔ 底盘

> **一句话本质：同一个速度矢量，在不同的坐标系里"看"，分量就不一样。**
> 旋转矩阵就是**换基**——把"云台眼里的速度"翻译成"车体眼里的速度"，或者反过来。

---

## 一、为什么底盘代码里处处都要它

| 场景 | 需要什么变换 |
|---|---|
| 云台指着左前方，你推摇杆"向前" | 车体该往**云台指的方向**走，不是车头方向 → 云台系 → 车体系 |
| 底盘自转（小陀螺），但平移方向要**锁在世界系** | 世界系 → 车体系（每周期都要转） |
| 底盘自转时云台要**保持指向不变** | yaw 电机要反向补偿 `-ω·dt` |
| 底盘速度前馈给云台 / 云台速度前馈给底盘 | 两个方向都要 |

**核心认识**：轮子解算（5.1~5.3）只认**车体系**的速度 `(vx, vy, ω)`。
所有"外来"的速度（遥控、上位机、云台系、世界系）**都必须先转成车体系**，才能进解算。

---

## 二、二维旋转矩阵

$$
R(\theta)=\begin{bmatrix}\cos\theta & -\sin\theta\\ \sin\theta & \cos\theta\end{bmatrix}
$$

**它的作用：把矢量从"相对参考系转了 θ"的坐标系，转到参考系。**

$$
\vec{v}_{\text{参考系}} = R(\theta)\,\vec{v}_{\text{转动系}}
$$

**两个必须记住的性质：**
1. **正交矩阵**：逆矩阵 = 转置 → `R(-θ) = R(θ)ᵀ`，反向变换不用重新推公式。
2. **方向约定**：`θ` 是**逆时针为正**（俯视）。**如果你的电机角度正方向是顺时针，第一件事就是取反。**

> 手算验证（记不住方向时就靠它）：
> 云台相对底盘**逆时针转了 90°**（云台指向车体的左边，即 `+y`）。
> 操作手在云台系里推"向前"`(1, 0)`：
> `R(90°)·(1,0) = (0, 1)` → 车体应该往 `+y`（左）走 ✅ 与"沿云台指向走"一致。

---

## 三、云台 ↔ 底盘（本节重点）

设 `θ` = 云台相对底盘的偏航角（逆时针为正，**弧度**）。

```c
/* ---------- 云台系 → 车体系：让底盘"按云台指向"运动 ---------- */
float c = cosf(theta), s = sinf(theta);
vx_body = c * vx_gimbal - s * vy_gimbal;
vy_body = s * vx_gimbal + c * vy_gimbal;

/* ---------- 车体系 → 云台系：把底盘运动"告诉"云台（前馈/补偿） ---------- */
vx_gimbal =  c * vx_body + s * vy_body;    /* R(θ)ᵀ */
vy_gimbal = -s * vx_body + c * vy_body;
```

**注意第二种写法就是逆变换**（转置），**别手写两套公式，容易一处符号写错**。

**`θ` 从哪来？** 三种常见来源，选一个并写进注释：
1. 云台 yaw 电机的**机械角度**（编码器，最可靠，但要处理零位与方向）
2. IMU 装在云台上测得的 yaw 减去底盘 IMU 的 yaw
3. 目标值（如果云台伺服足够快，用"命令角"近似也能跑）

---

## 四、和世界系打交道（小陀螺 / 矢量锁向）

设底盘相对世界的偏航角为 `ψ`（IMU yaw 累加值，逆时针为正）：

$$
\vec{v}_{\text{世界}} = R(\psi)\,\vec{v}_{\text{车体}},
\qquad
\vec{v}_{\text{车体}} = R(-\psi)\,\vec{v}_{\text{世界}}
$$

**典型用法：一边自转一边朝固定方向平移**

```c
/* 目标：在世界系里以 (vx_w, vy_w) 平移，同时以 w 自转 */
float psi = IMU_GetYawContinuous();          /* 连续角，不要用归一化后的角！ */
float c = cosf(-psi), s = sinf(-psi);

float vx_body = c * vx_w - s * vy_w;         /* 世界系 → 车体系 */
float vy_body = s * vx_w + c * vy_w;

Mecanum_Solve(vx_body, vy_body, w, v);       /* 再进运动学解算 */
```

**这一段的实际效果**：不管底盘转到哪个角度，平移方向在**地面**上保持不变——这就是"小陀螺不乱走"的实现原理。

### 云台指向补偿

底盘以 `ω` 自转时，云台要保持指向不变，yaw 电机必须**反向**追：

$$
\Delta\theta_{\text{motor}} = -\omega \cdot dt \times \text{减速比} \quad(\text{注意电机角度正方向})
$$

（或者更省事：直接给云台 yaw 一个**位置闭环**，目标 = 保持不变的绝对角，让 PID 去追。）

## 五、扩展到三维（先知道有这回事）

水平运动只用得上 2×2 矩阵。当要处理 **pitch**（比如云台上仰时给底盘做速度补偿、或者机械臂末端速度），就需要 3×3 旋转矩阵或**四元数**：

$$
R = R_z(\psi)\,R_y(\theta)\,R_x(\phi)
$$

**顺序不能交换**（先转哪个轴，结果不同）——所以要写清"Z-Y-X 还是 X-Y-Z"。
实际工程中：**只有在处理俯仰/翻滚时才需要 3D**，平面底盘运动别自己给自己加复杂度。

## 六、常见坑

1. **角度单位**：`cosf()` 要**弧度**；参数表里往往是**度** → 读进来立刻换算，别到处转。
2. **正方向相反**：电机角度递增可能是顺时针 → 本质上是"符号错"，表现为"越转越歪"。**用一组测试固定它。**
3. **用归一化角做旋转/微分**：角度从 179° 跳到 -179° 时，旋转结果会**突然翻转**。
   → 需要**连续角（unwrapped）**：累加 `Δθ = normalize(θ_now − θ_last)`，不要直接用归一化值。
4. **矢量变换 vs 点变换**：矢量（速度、力）只乘旋转矩阵；**点**（位置）要先减原点再转（还要平移）。
5. **两套公式手写两遍** → 一处符号错，排查半天。**用一个函数 + 转置。**
6. **`.f` 后缀与 `double` 混用**：STM32F4 上 `sinf/cosf` 走单精度 FPU，比 `sin/cos` 快很多（2.2.3、2.3.2）。
