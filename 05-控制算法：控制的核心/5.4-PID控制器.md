# 5.4 PID 控制器

> **一句话本质：PID 就是"根据误差大小、误差积累、误差变化趋势"来决定输出。**
> 目标 - 实际 = 误差；把误差的**现在、过去、未来**三种信息各乘一个系数加起来，就是输出。

---

## 一、三项分别在管什么

$$
u = K_p\,e + K_i\!\int e\,dt + K_d\frac{de}{dt},
\qquad e = \text{目标} - \text{实际}
$$

| 项 | 看的是 | 作用 | 单独用的后果 |
|---|---|---|---|
| **P** 比例 | 误差的**现在** | 误差越大，输出越大，反应快 | 总差一点点到不了（**稳态误差**）；`Kp` 太大就振荡 |
| **I** 积分 | 误差的**过去**（累积） | 把长期残余的误差磨掉 → 消除稳态误差 | 太大会**超调**、会**积分饱和**（windup） |
| **D** 微分 | 误差的**趋势**（变化率） | 提前"刹车"，抑制超调 | 对**噪声**极其敏感，编码器一量化就抖 |

**一句话记法**：P 是"现在"、I 是"过去"、D 是"未来"。

## 二、离散实现（单片机里真正跑的东西）

```c
typedef struct {
    float kp, ki, kd;
    float err_last;        /* 上一拍的误差，用来算微分 */
    float integral;        /* 积分累积 */
    float out_max;         /* 输出限幅（防止把电机/舵机打死） */
    float i_max;           /* 积分限幅（防止积分饱和） */
    uint8_t first;         /* 第一拍标记：避免微分项一上来就爆 */
} PID_t;

float PID_Calc(PID_t *p, float target, float actual, float dt)
{
    float err = target - actual;

    /* ---- 积分项：累积 + 限幅 ---- */
    p->integral += err * dt;
    if (p->integral >  p->i_max) p->integral =  p->i_max;
    if (p->integral < -p->i_max) p->integral = -p->i_max;

    /* ---- 微分项：误差的变化率 ---- */
    float d = 0.0f;
    if (!p->first) {
        d = (err - p->err_last) / dt;
    }
    p->first = 0;
    p->err_last = err;

    /* ---- 合成 + 输出限幅 ---- */
    float out = p->kp * err + p->ki * p->integral + p->kd * d;
    if (out >  p->out_max) out =  p->out_max;
    if (out < -p->out_max) out = -p->out_max;
    return out;
}
```

**注意 `dt` 必须稳定**：`Ki`、`Kd` 都依赖它。如果这个函数在 1 ms 定时器里调用，就永远在 1 ms 里调用——**不要"有时候 1 ms、有时候 20 ms"**，否则参数全部失效。

## 三、三个系数到底是什么（量纲直觉）

| 系数 | 单位 | 增大时 | 过大的表现 |
|---|---|---|---|
| `Kp` | 输出/误差 | 响应变快、误差变小 | 振荡、啸叫、发热 |
| `Ki` | 输出/(误差·秒) | 稳态误差消失得更快 | 超调、来回摆、积分饱和 |
| `Kd` | 输出·秒/误差 | 超调变小、更"稳" | 高频抖动（放大噪声） |

**为什么要清楚单位？** 因为换一个量纲就要重新调参：
把"目标速度"从 **RPM** 改成 **m/s**，`Kp` 的数值直接差几十倍——这就是"我昨天明明调好了，今天一换单位全废"的原因。

## 四、调参顺序（照着做，别跳步）

1. **只开 P**：从小到大加，直到出现**轻微等幅振荡**，然后退回到振荡起点的一半左右。
2. **加 I**：从很小开始加，观察稳态误差是否消失。**一出现超调变大/来回摆就退一点。**
3. **加 D（可选）**：只有"超调明显、看不出别的毛病"时才加。加 D 时**先给反馈量加低通滤波**。
4. **看波形验收**：上升时间、超调量、稳态误差、恢复时间——四个指标都要看一眼。

> **没有波形的调参 = 闭眼开车。** 用 Ozone / 上位机把"目标值、实际值、输出值"三条曲线画出来，
> 参数该往哪调一眼就看出来。这也是我们为什么要先学 Ozone（2.1.7）。

## 五、四个让 PID 真正好用的技巧

| 技巧 | 解决什么 | 怎么做 |
|---|---|---|
| **积分限幅** | 积分饱和（输出卡在限幅值，积分还在涨，松手后要"还债"） | `integral` 夹在 `±i_max`，或输出饱和时停止积分 |
| **积分分离** | 起步阶段误差巨大，积分一下冲太高 | `\|e\| > 阈值` 时不积 |
| **微分先行** | 目标突变时 D 项瞬间爆掉（微分冲击） | 改成对**反馈量**微分：`d = -(actual - actual_last)/dt` |
| **滤波** | 编码器量化噪声被 D 放大 | 对反馈做一阶低通：`y += α(x - y)`，`α` 取 0.1~0.3 |

**这四个都是在"上实车之前"就该写好的**，不是等出问题再补。

## 六、队里把这些 PID 用在哪

| 场景 | 目标 | 反馈 | 输出 |
|---|---|---|---|
| 底盘速度环 | 目标轮速（m/s） | 编码器实测速度 | 电流 / PWM |
| 底盘/云台位置环 | 目标角度 | 编码器角度 | 目标速度（串级用，见 5.5） |
| 云台角度环 | 目标 yaw/pitch | IMU 或电机角度 | 电流 / PWM |
| 平衡车姿态环 | 目标倾角（0） | IMU 倾角 | 轮子加速度 |

**同一个 `PID_Calc`，换个目标/反馈就是另一个控制器**——所以代码要写成可复用的结构体（就是上面的 `PID_t`）。

## 七、常见坑

1. **`dt` 不稳** → 参数怎么调都"差一口气"。
2. **忘了输出限幅 / 积分限幅** → 一上电全功率冲出去（真实事故现场）。
3. **积分变量用 `int`** → 小误差被截断成 0，稳态误差永远消不掉。
4. **微分项没滤波** → 电机嗡嗡响、发烫。
5. **单位与量纲变化后没重调** → "换了单位就废了"。
6. **测量噪声大就用大 `Kd` 硬压** → 越压越抖，正确做法是先滤波、再考虑 D。
7. **用 PID 去解决结构性缺陷**：比如重复精度差、齿轮间隙、传感器延迟——**这些 PID 治不好**。
   机械与传感器的问题，先修机械，再谈调参。
