# 5.7 重力补偿控制器

> **一句话本质：重力矩随角度变化，所以"保持不动的输出"也得随角度变化。**
> 补偿量天生就是 `K·cos(θ − θ₀)` —— **一个系数、一个角度，就能让云台"松手不掉"。**

---

## 一、先看现象：为什么云台会"抬头掉、低头冲"

云台的 pitch（俯仰）轴上挂着负载（枪管 / 云台头）。重力始终向下，而轴到负载质心的**力臂随角度变化**：

```
        ┌──────── 摆臂水平：力臂最大 → 重力矩最大 → 最容易下坠
        │
   ═════╪═════ 轴
        │
        └──────── 摆臂竖直：(几乎)没有力臂 → 重力矩≈0 → 不掉
```

结果就是：

- 只用一个固定 PID 参数 → **某些角度稳，某些角度一直往下掉或回不来。**
- 靠加大 `Kp` 硬顶 → 会在"力臂小"的角度剧烈振荡。

**这不是调参问题，是"被控对象的模型随角度变化"的问题。** 所以要用前馈（5.6）补上这个**已知的**重力矩。

---

## 二、模型：力矩就是一条余弦曲线

摆臂长度为 `L`、负载质量 `m`，摆臂与水平方向夹角为 `θ − θ₀`，则重力矩：

$$
M(\theta) = m\,g\,L\,\cos(\theta-\theta_0)
$$

| 符号 | 含义 |
|---|---|
| `m·g·L` | 一个**常数**（质量、重力加速度、力臂长度都不变） |
| `θ` | 当前角度（IMU 或电机编码器给） |
| `θ₀` | **重力矩最大**的那个角度（摆臂正好水平时） |

所以补偿输出就长这样：

$$
u_{\text{重力}} = K\cos(\theta-\theta_0)
$$

**`K` 和 `θ₀` 两个参数，标定完就固定了。** 剩下的事就是每个周期算一次 `cos`——**比调 PID 便宜太多了**。

---

## 三、标定：两步搞定

### ① 找 `θ₀`
把云台摆到**摆臂水平**的位置（目视或用水平仪），读此时的角度 → 这就是 `θ₀`。
（也可取"重力矩最大"的位置为 `θ₀ = 0`，把 `θ` 重新定义为相对角，公式更简单：`u = K·cos(θ)`。）

### ② 标 `K`
1. 把 PID 暂时关掉（或把姿态控制放开），让云台停在 `θ₀`（最容易下坠的角度）。
2. **手动慢慢加大**补偿输出，直到云台**刚好不下坠、也不会自己往上冲**。
3. 记下这个输出值 → 它就是 `K`。
4. 在另一个角度（比如偏离 60°）验证：`K·cos(60°) = 0.5K`，看是否也刚好顶住。

> 若两处对不上，说明零位 `θ₀` 有偏差（或存在摩擦），微调 `θ₀` 再试。

```c
typedef struct {
    float k;         /* 重力补偿系数（标定得到） */
    float theta0;    /* 重力矩最大的角度（弧度） */
} GravComp_t;

float Grav_Compensate(GravComp_t *g, float theta)
{
    return g->k * cosf(theta - g->theta0);      /* θ、θ₀ 都用弧度！ */
}
```

**`K` 与 `θ₀` 一定要存 Flash**（掉电不丢，见 2.3.3）——换个负载、换个枪管就要重标，参数必须能改。

---

## 四、和 PID 怎么配合

```c
float out = Grav_Compensate(&grav, now_theta)     /* 重力前馈：大头 */
          + PID_Calc(&angle_pid, target, now_theta, dt);   /* 反馈：修残差 */
```

**带来的好处（和 5.6 一样）：**

| | 只有 PID | 加重力补偿后 |
|---|---|---|
| `Kp` | 必须很大才能顶住重力 | 可以取小 |
| 各角度一致性 | 差异很大（水平位抖、竖直位无力） | 基本一致 |
| 掉电/急停瞬间 | 云台猛地砸下来 | 无改善（前馈也断电了）→ **急停要另做机械保护** |

---

## 五、顺带补上摩擦补偿（小改动，大提升）

小角度、低速时，**静摩擦**会让云台"卡住不动"，PID 要积累很久误差才能推动它。加一项摩擦补偿立刻改善：

```c
/* 库仑摩擦：只要想动，就先给出"克服静摩擦"的那部分 */
if (fabsf(err) > 死区阈值) {
    out += (err > 0.0f) ? k_fric : -k_fric;
}
```

> 摩擦补偿配合重力补偿，能把云台的"手感"从"生涩"变成"顺滑"——这是很多队伍云台表现的差距所在。

---

## 六、常见坑

1. **单位混用**：`cosf()` 要**弧度**，但界面/参数表里常写角度 → 一定要在读参数时 `×π/180`。
2. **符号错**：抬头和低头的补偿方向相反。**先手动验证再上车。**
3. **零位 `θ₀` 随机械装配变化** → 换结构、重新装配后必须重标（写进装配检查表）。
4. **负载变了没重标**：加了图传、换了枪管，`K` 就变了 → **把标定做成可随时执行的流程**。
5. **只补重力不补摩擦** → 小角度仍有死区，看着像"PID 没调好"。
6. **想用重力补偿解决"急停砸下来"** → 做不到。断电后没有任何软件补偿，**必须靠机械配重/弹簧/限位**。
7. **`cos` 算在中断里却频率很高** → 浮点 `cosf` 有一定开销，1 ms 一次没问题；若在更高频的循环里算，考虑查表。
