# 00 · SPR 电控组培训总纲 —— 你的两年成长地图

> 这份总纲是整个培训的**地图**。它不教你怎么写代码，它告诉你：这两年，你会被变成什么样的人，这条路怎么走。
> 建议每学完一章，回来对照一次——看看自己走到地图的哪里了。

---

## 一、两年后，你会成为什么样的人

我们不培养"调通代码的人"，我们培养拥有四种能力的人——它们**离开赛场依然跟着你走**：

1. **完善的思考体系** —— 遇到任何没见过的模块（新传感器、新电机、新芯片），你知道怎么一步步把它拆开、搞懂。不是"照教程抄"，是"我自己能想明白"。
2. **法医式诊断能力** —— 东西坏了不慌。先让 bug 稳定复现，再用"砍掉一半可能性"的方法缩小范围，用数据和日志说话，而不是靠猜和拍桌子。
3. **AI 与信息检索** —— 遇到不会的，知道去哪查、怎么问 AI、怎么验证 AI 没骗你。2026 年的工程师，拼的不是记忆力，是"快速找到正确答案"的能力。
4. **行业视野** —— 你知道自己焊的板子、调的电机，在整个机器人行业里处于什么位置，别人正在往哪走。

你不是来当"写代码的码农"的，你是来成为**系统的集成交付方**——让整台机器活起来、可靠地完成任务的那个人。

## 二、这条路怎么走（培训地图）

整个培训分 9 站加一个弹药库，每一站都有明确目标：

| 站 | 主题 | 这一站结束时，你做到什么 |
|---|---|---|
| 01 认知篇 | 重新认识"电控" | 讲清楚电控在整个机器人里的角色和边界 |
| 02 动手关 | 第一台能"动"的机器 | 让代码第一次控制物理世界（LED / 电机 / 串口） |
| 03 工程素养 | 公司化流程 | 从"能跑"升级到"能交付" |
| 04 外设 | STM32 核心外设 | 用工具解决真实场景问题 |
| 05 通信 | 让芯片"说话" | 让多个芯片可靠地协同工作 |
| 06 控制 | 调参哲学 | 让电机听你的话，并知道为什么 |
| 07 架构 | 代码组织 | 代码超过一千行也不乱 |
| 08 诊断 | 法医式排查 | 故障到你手里，不再是玄学 |
| 09 协作 | 赛季管理 | 一个人撑不起一个赛季，学会靠机制 |
| 10 附录 | 资源库 | 随用随查的弹药库 |

## 三、我们怎么共事（四条底线）

1. **提问必须带排查记录** —— "我做了 A，观察到 B，排除了 C"。没有排查记录的提问，电控组不受理。
2. **改了什么必须留痕** —— Git 提交写清楚、参数变更同步更新。你两个月后的自己，靠这些记录活着。
3. **事故现场优先于情绪** —— 先切断动力、保存现场（日志 / 寄存器）、再断电复盘。数据还在，真相就还在。
4. **交付物要能讲清楚** —— 不只是"能跑"，还要能讲清"为什么这么写、别的方式为什么不行"。

## 四、写在出发前

> 你写下的每一行超时判断，背后是几万块的电机，和队友一年的青春。
> 这条路不难走，但每一步都要踩实。走完 10 站，你就是能独当一面的电控工程师。
