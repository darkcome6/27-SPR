## 篇一 · 往上走：控制的上限在哪？

1. **MIT Cheetah 跑酷** —— 四足机器人在复杂地形奔跑、跳跃、翻越障碍。底层是 MPC + 全身控制。
2. **宇树 H1 / 特斯拉 Optimus 行走** —— 人形机器人的动态平衡，控制算法在真实硬件上落地。
3. **⚠️ 机器人摔倒 / 控制失稳合集** —— 没有好的控制，会怎样？

> 看的时候注意：每一次落脚、每一次重心转移，都不是人写死的规则，而是**算法自己算出来的**。这就是控制理论在"上面"的样子。
> 记住失败合集里的画面——**没有好的控制，前面那些"酷"全都不存在。**

---

## 篇二 · 往下走：控制的下限在哪？

1. **大疆 RoboMaster 电机 CAN 响应** —— 发一条指令，电机在几毫秒内执行。
2. **互补滤波 vs 卡尔曼滤波（姿态解算）** —— "滤波"是把原始数据变成可用信息的过程。
3. **多传感器融合（GPS + IMU + 轮速）** —— 多个来源的数据拼在一起，得出更可靠的结论。

> 这些画面没有上一篇那么"酷"，但它们是所有"酷"的基础。**没有稳定的底层控制，上层的算法再强也落不了地。**

---

## 篇三 · 连接：仿真到实体

1. **MuJoCo 物理仿真** —— 算法在仿真里先跑几百万次，才敢上真机。
2. **Sim-to-Real 迁移** —— 同一个算法在仿真和真实世界里的对比。

> 为什么需要仿真？**真机摔一次修几万块，仿真里摔一百万次只耗电费。**

---

2. **SPR 往年比赛 / 调试片段** —— 我们现在的位置。

## 电控能力地图

```
┌─────────────────────────┐
│  强化学习 / 神经网络        │ ← 顶层：算法自己学
│  MPC / LQR               │ ← 上层：最优控制
│  MuJoCo / 仿真            │ ← 桥梁：先在虚拟世界跑
├─────────────────────────┤
│  状态估计 / 滤波           │ ← 中间：把传感器读懂
│  数据解包 / 协议           │ ← 底层：听懂机器说的话
│  电机控制 / PWM           │ ← 最底层：让物理世界动起来
└─────────────────────────┘
```

这就是电控在技术栈里的**真实跨度**。

- 最底层让电机转——**这是你们这学期马上要学的**。
- 最顶层让机器人自己学会走路——**那是你们四年后可能到达的地方**。
- 中间隔着的所有东西，都叫**电控**。
