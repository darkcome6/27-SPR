## 小组讨论（20 分钟）

回到开篇的问题：

> **"电控是干什么的？"——现在，你们会怎么回答？**

可以看见，所谓的电控的工作并不只是 “电机控制”，而是可以分成很多层
第一层 ，采集处理传感器数据（IMU，压力传感器...）执行器数据（关节电机），之后对这些数据及解包
第二层 ，将数据传入你的控制器（IMU结算函数，PID,LQR滑模控制算法），通过计算再传出数据，该给执行器多大的扭矩/电流
上面两个主要任务之外 ，仿真，模型预测，以及其他的各种辅助你开发的任务也同样是电控的职能范围

## 电控能力地图

```
┌─────────────────────────┐
│  强化学习 / 神经网络        │ ← 顶层：算法自己学
│  MPC / LQR               │ ← 上层：最优控制
│  MuJoCo / 仿真            │ ← 桥梁：先在虚拟世界跑
├─────────────────────────┤
│  状态估计 / 滤波           │ ← 中间：把传感器读懂
│  数据解包 / 协议           │ ← 底层：听懂机器说的话
│  电机控制 / PWM           │ ← 最底层：让物理世界动起来
└─────────────────────────┘
```

这就是电控在技术栈里的**真实跨度**。

- 最底层采数据让电机转——**这是你们这学期马上要学的**。
- 最顶层让机器人自己学会走路——**那是你们四年后可能到达的地方**。
- 中间隔着的所有东西，都叫**电控**。
