# 3.0 Keil 常用功能速览

> **一句话本质：Keil 是一个"编辑 + 编译 + 下载 + 调试"的一体机。**
> 它最大的价值不在"写代码"，而在**调试**——能让你亲眼看见变量和寄存器的值。

---

## 一、先说清楚：为什么还要学 Keil

2.1 里我们说过：**VSCode + EIDE + GCC 是主力，Keil 是保底。** 那为什么这一节还要讲它？

1. **队里的老工程、别人的例程大量是 Keil 工程**，看不懂你就不敢重构。
2. **救急**：VSCode 环境炸了、电脑没装 GCC 的时候，Keil 能让你马上开工。
3. **它的调试器很好用**，很多同学第一次"看见寄存器"就是在 Keil 里。
4. **厂商和面试官都用它**：ST 官方例程、各种教程、面试题基本以 Keil 为背景。

> Keil 是"新手村武器"——上手快，但出了新手村就换成 VSCode。
> **不过"调试的思维"（断点、看变量、看寄存器）是通用的**，换个 IDE 一样用。

## 二、界面地图

```
┌─────────────────────┬───────────────────────────────┐
│  Project 窗口        │        代码编辑区              │
│  （工程树）           │                               │
│   ├─ Application     │   void main(void) {           │
│   ├─ Drivers         │       HAL_Init();             │
│   ├─ CMSIS           │   }                           │
│   └─ ...             │                               │
├─────────────────────┴───────────────────────────────┤
│  Build Output（编译输出）：报错、警告、占用统计都在这里  │
└─────────────────────────────────────────────────────┘
```

**你只需要先认清三块**：工程树（有哪些文件）、编辑区（写代码）、Build Output（出问题时看这里）。

`Project 窗口里没有的 .c 文件，等于不存在`——**"我明明写了这个函数，为什么 `undefined reference`？"** 八成是文件没加进工程（呼应 2.2.7）。

## 三、工具栏上那四个按钮

| 按钮 | 作用 | 什么时候点 |
|---|---|---|
| **Build**（F7） | 只编译**改动过的**文件 | 日常 |
| **Rebuild** | **全部**重新编译 | 改了 `.h`、改了宏、`.o` 状态可疑时——**"改了没生效"先点它** |
| **Download / Load**（F8） | 把你编出来的程序烧进 Flash | 编译成功后 |
| **Start Debug**（Ctrl+F5） | 进入调试模式 | 程序行为不对时 |

> 快捷键在不同版本里可能略有差异，**以菜单按钮上的提示为准**。
>
> 顺序永远是：**Build → Download → 复位运行。**

## 四、调试：Keil 最值钱的十个功能

进入调试模式后，你会用到这些：

| 功能 | 是什么 | 怎么用 |
|---|---|---|
| **断点 Breakpoint** | 让程序跑到这行就停下 | 点行号左边（F9） |
| **Run / Stop** | 继续 / 暂停 | F5 |
| **Step（单步跳过）** | 执行一行，不进函数内部 | F10 |
| **Step Into（单步进入）** | 执行一行，遇到函数就**进去** | F11 |
| **Step Out（跳出）** | 从当前函数里跳回上一层 | Ctrl+F11 |
| **Run to Cursor** | 一路跑到光标那行 | Ctrl+F10 |
| **Watch 窗口** | **盯住一个变量，实时看它的值** | 输入变量名即可 |
| **Locals / Call Stack** | 看当前函数的局部变量和调用链 | 自动显示 |
| **Memory 窗口** | 按地址看内存内容 | 输入 `0x20000000` 之类 |
| **Peripheral 窗口** | **直接看外设寄存器**（GPIOA/ODR、TIM3/CNT…） | 勾选对应外设名 |

### 为什么 Peripheral 窗口是"验尸神器"

引脚不动？不用改一行代码，直接在 Peripheral 窗口里看：

- **MODER** 里那个引脚是输入还是输出？（配错 → 永远是输入）
- **ODR** 有没有按你想的翻转？（没变 → 你的代码根本没执行到）
- **RCC** 里的外设时钟开了没？（没开 → 后面全白配，呼应 2.3.4）

**现象 → 看寄存器 → 定位到"配置错了"还是"代码没跑到"**，这一步比你瞎猜快十倍。

## 五、顺手看懂 Build Output 里的那行统计

编译成功后会有类似这样一行：

```
Program Size: Code=12345 RO-data=678 RW-data=90 ZI-data=2048
```

它正好对应 2.3.3 讲的段：

| 名字 | 是什么 | 住在哪 |
|---|---|---|
| `Code` | 机器码（`.text`） | Flash |
| `RO-data` | 只读常量 | Flash |
| `RW-data` | **有初值**的全局/静态变量（`.data`） | 初值在 Flash，运行时在 RAM |
| `ZI-data` | **初值为 0 / 未写初值**的全局/静态变量（`.bss`） | RAM |

**粗略估算**：Flash ≈ `Code + RO-data + RW-data`；RAM ≈ `RW-data + ZI-data` + 栈。
→ "RAM 是不是要爆了"，看一眼这行就有数。

## 六、三个必须检查的工程设置（Options for Target）

| 设置项 | 在哪 | 为什么重要 |
|---|---|---|
| **下载器** | Debug → Use | 选 `J-LINK / J-LINK` 或 ST-Link，选错下载直接失败 |
| **晶振频率** | Debug → Settings 里的时钟 | 填错 → 调试器显示的运行时间、延时全都不是真的 |
| **Reset and Run** | Utilities → Settings | 不勾：下载完程序**停在原地不动**，你会以为"没烧进去" |

> 新手经典迷惑："下载成功了，但板子没反应。"
> 一半原因是没勾 **Reset and Run**，另一半是**忘了 Build 就 Download**。

## 七、常见坑

1. **改了 `.h` 没 Rebuild** → 现象：改了代码没效果（`.o` 没重新生成）。
2. **忘了 Build 直接 Download** → 烧的是上一次的程序。
3. **优化等级开太高（`-O2` 以上）** → 断点乱跳、某些变量"看不了"（被优化掉了）。
   **调试阶段用 `-O0`**，发布再开优化。
4. **想看中断里改的变量却看不到变化** → 变量没加 `volatile`（2.2.8）。
5. **文件没加进工程** → 编译通过但链接报 `undefined reference`。
