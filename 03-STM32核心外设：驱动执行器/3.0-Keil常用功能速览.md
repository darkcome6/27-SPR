# 3.0 Keil 常用功能速览

> **一句话本质：Keil 是一个"编辑 + 编译 + 下载 + 调试"的一体机。**
> 它最大的价值不在"写代码"，而在**调试**——能让你亲眼看见变量和寄存器的值。

---

## 一、先说清楚：为什么还要学 Keil

2.1 里我们说过：**VSCode + EIDE + GCC 是主力，Keil 是保底。** 那为什么这一节还要讲它？

1. **队里的老工程、别人的例程大量是 Keil 工程**，看不懂你就不敢重构。
2. **救急**：VSCode 环境炸了、电脑没装 GCC 的时候，Keil 能让你马上开工。
3. **它的调试器很好用**，很多同学第一次"看见寄存器"就是在 Keil 里。
4. **厂商和面试官都用它**：ST 官方例程、各种教程、面试题基本以 Keil 为背景。

> Keil 是"新手村武器"——上手快，但出了新手村就换成 VSCode。
> **不过"调试的思维"（断点、看变量、看寄存器）是通用的**，换个 IDE 一样用。

## 二、界面地图

```
┌─────────────────────┬───────────────────────────────┐
│  Project 窗口        │        代码编辑区              │
│  （工程树）           │                               │
│   ├─ Application     │   void main(void) {           │
│   ├─ Drivers         │       HAL_Init();             │
│   ├─ CMSIS           │   }                           │
│   └─ ...             │                               │
├─────────────────────┴───────────────────────────────┤
│  Build Output（编译输出）：报错、警告、占用统计都在这里  │
└─────────────────────────────────────────────────────┘
```

**你只需要先认清三块**：工程树（有哪些文件）、编辑区（写代码）、Build Output（出问题时看这里）。

`Project 窗口里没有的 .c 文件，等于不存在`——**"我明明写了这个函数，为什么 `undefined reference`？"** 八成是文件没加进工程（呼应 2.2.7）。

## 三、工具栏上那四个按钮

| 按钮 | 作用 | 什么时候点 |
|---|---|---|
| **Build**（F7） | 只编译**改动过的**文件 | 日常 |
| **Rebuild** | **全部**重新编译 | 改了 `.h`、改了宏、`.o` 状态可疑时——**"改了没生效"先点它** |
| **Download / Load**（F8） | 把你编出来的程序烧进 Flash | 编译成功后 |
| **Start Debug**（Ctrl+F5） | 进入调试模式 | 程序行为不对时 |

> 快捷键在不同版本里可能略有差异，**以菜单按钮上的提示为准**。
>
> 顺序永远是：**Build → Download → 复位运行。**

## 四、调试：Keil 最值钱的十个功能

进入调试模式后，你会用到这些：

| 功能 | 是什么 | 怎么用 |
|---|---|---|
| **断点 Breakpoint** | 让程序跑到这行就停下 | 点行号左边（F9） |
| **Run / Stop** | 继续 / 暂停 | F5 |
| **Step（单步跳过）** | 执行一行，不进函数内部 | F10 |
| **Step Into（单步进入）** | 执行一行，遇到函数就**进去** | F11 |
| **Step Out（跳出）** | 从当前函数里跳回上一层 | Ctrl+F11 |
| **Run to Cursor** | 一路跑到光标那行 | Ctrl+F10 |
| **Watch 窗口** | **盯住一个变量，实时看它的值** | 输入变量名即可 |
| **Locals / Call Stack** | 看当前函数的局部变量和调用链 | 自动显示 |
| **Memory 窗口** | 按地址看内存内容 | 输入 `0x20000000` 之类 |
| **Peripheral 窗口** | **直接看外设寄存器**（GPIOA/ODR、TIM3/CNT…） | 勾选对应外设名 |

### 为什么 Peripheral 窗口是"验尸神器"

引脚不动？不用改一行代码，直接在 Peripheral 窗口里看：

- **MODER** 里那个引脚是输入还是输出？（配错 → 永远是输入）
- **ODR** 有没有按你想的翻转？（没变 → 你的代码根本没执行到）
- **RCC** 里的外设时钟开了没？（没开 → 后面全白配，呼应 2.3.4）

**现象 → 看寄存器 → 定位到"配置错了"还是"代码没跑到"**，这一步比你瞎猜快十倍。

## 五、顺手看懂 Build Output 里的那行统计

编译成功后会有类似这样一行：

```
Program Size: Code=12345 RO-data=678 RW-data=90 ZI-data=2048
```

它正好对应 2.3.3 讲的段：

| 名字 | 是什么 | 住在哪 |
|---|---|---|
| `Code` | 机器码（`.text`） | Flash |
| `RO-data` | 只读常量 | Flash |
| `RW-data` | **有初值**的全局/静态变量（`.data`） | 初值在 Flash，运行时在 RAM |
| `ZI-data` | **初值为 0 / 未写初值**的全局/静态变量（`.bss`） | RAM |

**粗略估算**：Flash ≈ `Code + RO-data + RW-data`；RAM ≈ `RW-data + ZI-data` + 栈。
→ "RAM 是不是要爆了"，看一眼这行就有数。

## 六、必须检查的工程设置（Options for Target）

| 设置项 | 在哪 | 为什么重要 |
|---|---|---|
| **下载器** | Debug → Use | 选 `J-LINK / J-LINK` 或 ST-Link，选错下载直接失败 |
| **晶振频率** | Debug → Settings 里的时钟 | 填错 → 调试器显示的运行时间、延时全都不是真的 |
| **Reset and Run** | Debug → Settings → Flash Download（或 Utilities → Settings） | 不勾：下载完程序**停在原地不动**，你会以为"没烧进去" |

> 新手经典迷惑："下载成功了，但板子没反应。"
> 一半原因是没勾 **Reset and Run**，另一半是**忘了 Build 就 Download**。

### Debug 标签（连接调试器）
![alt text](/03-STM32核心外设：驱动执行器/图库/image-5.png)

### 先分清两层：这个界面里有"两条链"

```
[电脑] ──USB── [J-Link / ST-Link 调试器] ──SWD 4 根线── [STM32 芯片]
            ①                                        ②
```

| 报错 | 卡在哪一层 | 要查什么 |
|---|---|---|
| `No J-link found` | **① 电脑 ↔ 调试器** | USB 线、驱动、有没有被别的程序占用 |
| `No Cortex-M SW Device Found`<br>`Could not stop Cortex-M device` | **② 调试器 ↔ 芯片** | SWD 连线、芯片供电、SWD 引脚被程序占用了 |

**判读口诀：先看左边 `J-Link / J-Trace Adapter` 那一排有没有值**（`SN` / `Device` / `HW` / `dll` / `FW`）。

| 你插了吗 | 界面会显示 | 卡在哪层 |
|---|---|---|
| 什么都没插 | 左边那一排**全空**，右边报 `No J-link found` | ① |
| 插了调试器，但芯片没连 / 没供电 | 左边那一排**有值了**，右边报 `No Cortex-M SW Device Found` | ② |
| 都通了 | 右边 `ID CODE` **有值**，`Device Name` 显示芯片型号 | ✅ 可以下载调试 |

### 三个最容易看错的地方

**① `Max: 500 kHz` 是调试时钟，不是芯片主频**

它是**电脑 ↔ 芯片之间 SWD 通信的频率上限**，和芯片主频（168 MHz）**毫无关系**。
它只影响两件事：**下载速度**、**调试时看变量的流畅度**。

| 情况 | 怎么做 |
|---|---|
| 不确定 | 点 **`Auto Clk`**，让 J-Link 自己协商（**推荐**） |
| 稳了想快 | 手动填 `4000`（kHz） |
| **连不上** | 往**低**调：`1000` → `500` → `100`（线长、杜邦线质量差、有干扰时，高速会连不上） |

**② `Device` 是"调试器的型号"，不是芯片型号！**

| 位置 | 是什么 | 例子 |
|---|---|---|
| `J-Link / J-Trace Adapter` → `Device` | **调试器的型号** | `J-Link / J-Link OB` |
| `SW Device` → `Device Name` | **目标芯片型号**（只有手动配置才填） | `STM32F407VG` |

旁边 `HW` / `dll` / `FW` 分别是硬件版本 / 驱动版本 / 固件版本 —— **空着就是没连上**。

**③ `Connect: Normal` —— 连不上时改成 `under Reset`**

如果程序一上电就把 SWD 引脚（`PA13`/`PA14`）复用成了别的功能，或者程序跑飞卡死，`Normal` 是**连不上**的。
这时把 `Connect` 改成 **`under Reset`**，再勾上 `Reset after Connect` —— 让芯片**一直保持复位**，调试器趁机连进去。

> **这是"板子刷死了救回来"的标准操作，一定要记住。**

### `No J-link found` 的排查顺序

1. **调试器的灯亮不亮？** 插上 USB 后电源灯应常亮。不亮 → 换 USB 口 / 换线
2. **换一个 USB 口，别用 Hub 或延长线**
3. **关掉所有可能占用它的程序**：Ozone、J-Link Commander、STM32CubeProgrammer、另一个 Keil 窗口、VSCode 的调试会话
   → **J-Link 是独占的**，被占着别人就连不上（**最常见的原因**）
4. **设备管理器**里有没有黄色叹号 → 有就是**驱动没装**，重跑 J-Link 安装包
5. 前四步都试过 → 用 J-Link 安装包自带的 **J-Link Commander** 单独连一次：它能连上说明是 Keil 的问题；它也连不上，就是硬件 / 驱动的问题

### 其余几项（默认就好）

| 项 | 说明 |
|---|---|
| `Cache Code` / `Cache Memory` | Keil 缓存代码 / 内存，看变量更快。默认（`Cache Memory` 勾上）就行 |
| `Verify Code Download` / `Download to Flash` | 通常**不勾** —— 对应设置在 `Flash Download` 标签里（下一节） |
| `Scan` | 重新搜索调试器（插拔 USB 后不用重启 Keil） |
| `JLink Info` | 连它都报错 → 是**驱动层面**的问题，别再怀疑工程配置 |

### 顺手搞懂 `Flash Download` 标签（烧录配置）
![alt text](/03-STM32核心外设：驱动执行器/图库/image-4.png)
入口：`Options for Target` → `Debug` 标签 → 右边 `Settings` → `Flash Download`
（`Debug` 管"怎么连上芯片"，`Flash Download` 管"连上之后怎么把程序写进 Flash"。）

| 选项 | 是什么 | 怎么选 |
|---|---|---|
| `Erase Full Chip` | 下载前把**整片 Flash 擦光** | 芯片跑飞 / 被锁 / 换别人的程序时用；最干净，也最慢 |
| `Erase Sectors` | 只擦**要写入的那几个扇区** | ✅ **日常用这个**：快，而且不动其它区域 |
| `Do not Erase` | 不擦，直接写 | ⚠️ 几乎不用 —— Flash 只能把 1 写成 0，没擦干净写进去就是错的 |
| `Program` | 真的把程序写进去 | ✅ 必须勾（不勾 = 只擦不写） |
| `Verify` | 写完**回读校验** | ✅ 建议勾，能当场发现"写坏了" |
| `Reset and Run` | 写完自动复位并运行 | ✅ 新手必勾 |

> 推荐组合就是默认那一组：`Erase Sectors` + `Program` + `Verify` + `Reset and Run`。

**两个没人讲、但你该知道的地方：**

- **`RAM for Algorithm`（`0x20000000` / `0x1000`）** —— 烧 Flash 时，芯片里要**跑一小段程序**：Keil 临时塞进 RAM 的"Flash 编程算法"，由它按芯片时序去擦、去写。这两格就是放它的位置和大小。（`0x20000000` 就是 SRAM 起始地址，见 2.3.3。）**新手不用改。**
- **`Programming Algorithm`（`STM32F4xx 1MB Flash` 那一行）** —— 不同芯片的擦写时序完全不同，Keil 得有对应的算法才知道怎么跟它说话。`08000000H - 080FFFFFH` 就是 STM32 的 Flash 地址范围（见 2.2.7）。
  **换板子 / 换型号后下载失败**（`Flash Download failed` / `Contents mismatch`）→ 先来这里 `Add` 正确的算法，多余的用 `Remove` 删掉。

**下载出问题，先查哪一格：**

| 症状 | 先查这里 |
|---|---|
| 下载成功，但板子没反应 | `Reset and Run` 没勾 / 忘了 Build |
| 报 `Flash Download failed` | `Programming Algorithm` 选错芯片 |
| 下载特别慢 | 用了 `Erase Full Chip`，换成 `Erase Sectors` |
| 写进去的值不对 | 没勾 `Verify`，或 `Do not Erase` 没擦干净 |
| 芯片被锁、怎么都连不上 | 用 STM32CubeProgrammer 全片擦除 |

## 七、常见坑

1. **改了 `.h` 没 Rebuild** → 现象：改了代码没效果（`.o` 没重新生成）。
2. **忘了 Build 直接 Download** → 烧的是上一次的程序。
3. **优化等级开太高（`-O2` 以上）** → 断点乱跳、某些变量"看不了"（被优化掉了）。
   **调试阶段用 `-O0`**，发布再开优化。
4. **想看中断里改的变量却看不到变化** → 变量没加 `volatile`（2.2.8）。
5. **文件没加进工程** → 编译通过但链接报 `undefined reference`。
