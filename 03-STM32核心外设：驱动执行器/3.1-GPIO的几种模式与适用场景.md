# 3.1 GPIO 的几种模式与适用场景

> **一句话本质：每根引脚内部都是一小堆"开关"，配置模式 = 把这些开关拨到正确的位置。**
> **配置的核心不是记名字，而是想清楚："这根线要干什么？"**

---

## 一、先建立模型：引脚内部长什么样

一根 GPIO 引脚内部，大致有几个可拨的开关（对应 2.3.5 讲的寄存器）：

```
                 ┌────────────── VDD（3.3V）
                 │
              [上拉开关]   ← PUPDR：要不要上拉
                 │
   引脚 ─────────┼──────────> [输出驱动] ──> 写 ODR/BSRR 决定输出高低
    │            │                ↑
    │         [下拉开关]        [模式开关]  ← MODER：输入 / 输出 / 复用 / 模拟
    │            │
    │            └────────────── GND
    │
    └──> [输入缓冲] ──> 读 IDR 得到引脚当前电平
```

所以**配一个引脚 = 回答四个问题**：

1. 它是**输入**还是**输出**？（`MODER`）
2. 输出时，是**推挽**还是**开漏**？（`OTYPER`）
3. 要不要**上拉 / 下拉**？（`PUPDR`）
4. 输出翻转要多**快**？（`OSPEEDR`）

## 二、四种"模式"到底在说什么

### 1. 输入类

| 模式 | 含义 | 什么时候用 |
|---|---|---|
| **浮空输入** | 什么都不接（高阻），电平由外部电路决定 | 外部电路**已经有**明确电平（如外部上拉电阻） |
| **上拉输入** | 内部接一个电阻到 VDD，默认读到**高** | 按键接 GND、串口 RX |
| **下拉输入** | 内部接一个电阻到 GND，默认读到**低** | 按键接 VDD |
| **模拟输入** | 断开数字电路，直接送给 ADC | 采电压（电池电压、电流检测） |

> **为什么一定要"上拉 / 下拉"？**
> 引脚悬空时，它读到的电平是**随机的**——手靠近都会变。接上拉/下拉，就是给它一个**确定的默认值**。
> **"按键自己乱触发"十有八九是浮空输入没配上下拉。**

### 2. 输出类：推挽 vs 开漏（重点）

| | **推挽（Push-Pull）** | **开漏（Open-Drain）** |
|---|---|---|
| 内部结构 | 上管 + 下管都有 | **只有下管**（只能主动拉低） |
| 能否主动输出高 | ✅ 能（接到 VDD） | ❌ 不能，高电平要靠**外部上拉电阻** |
| 驱动能力 | 强 | 弱（靠上拉电阻供电） |
| 特点 | 简单直接 | ① 多个设备可以**共享一根线**（线与）② 方便**电平转换**（上拉到 5V 就输出 5V） |

**记忆口诀**：
- **我要驱动一个东西**（LED、驱动器使能脚）→ **推挽**
- **多个设备要共用一根线 / 要跟不同电压的器件通信** → **开漏 + 上拉**

### 3. 复用功能（最重要的一个概念）

引脚不止能当"普通 IO"，它还能"交给外设用"——**串口的 TX、定时器的 PWM 输出，用的都是同一根引脚**。

- 复用**推挽**：交给外设，且是推挽输出（串口 TX、SPI、PWM）
- 复用**开漏**：交给外设，且是开漏输出（**I2C**）
- 复用**输入**：交给外设接收（串口 RX、SPI MISO）

> **关键认识：一个引脚同一时刻只能干一件事。**
> 你把它配成 GPIO 输出，它就不是串口 TX 了。这也是"引脚冲突"的根源（3.2 与 2.3.6 都会提到）。

### 4. 模拟：模拟输入

ADC 要测真实电压，数字输入电路会带来干扰和额外功耗，所以**采电压时必须配成模拟输入**。

## 三、场景对照表（本节的核心交付）

**这张表是本章最该背下来的东西。**（以 STM32F4 + CubeMX 的选项名为例）

| 用途 | 模式 | 为什么 |
|---|---|---|
| LED | 推挽输出 | 要主动输出高低，驱动电流小 |
| 电机的**方向 / 使能脚**（DIR、EN） | 推挽输出 | 驱动器输入是数字信号，需要明确高低 |
| **PWM 输出给电机驱动器 / 电调** | **复用推挽** | 引脚交给定时器，不是普通 IO |
| **PWM 输出给舵机** | **复用推挽** | 同上 |
| **串口 TX** | **复用推挽** | 由 USART 接管，需要主动驱动线 |
| **串口 RX** | **浮空输入** 或 **上拉输入** | 空闲时线是高电平；上拉可防悬空误触发 |
| **I2C 的 SCL / SDA** | **复用开漏** + 上拉（外部或内部） | 总线上多个器件共享一根线，必须"线与" |
| SPI 的 SCK / MOSI | 复用推挽 | 主机主动驱动，速度高 |
| SPI 的 MISO | 复用输入（浮空 / 上拉） | 由从机驱动 |
| 编码器 A / B 相 | 上拉输入（或直接交给定时器的编码器模式） | 防悬空抖动、计数更可靠 |
| 按键（按下接 GND） | 上拉输入 | 给出确定的默认高电平 |
| 按键（按下接 VCC） | 下拉输入 | 同理 |
| 电池电压 / 电流检测（ADC） | **模拟输入** | 数字电路会干扰测量 |
| 蜂鸣器、继电器（低边开关） | 推挽输出 | 主动驱动 |
| 多个器件共享一根报警/中断线 | 开漏输出（或上拉输入） | 线与：任何一个拉低，主机就能发现 |

> **一句话选型逻辑**：
> **驱动别人 → 推挽；多人共用一根线 → 开漏；读外部信号 → 上/下拉输入；测电压 → 模拟；交给外设 → 复用。**

## 四、什么时候"不能随便配"

1. **引脚被外设占用了**：CubeMX 里会标黄/报冲突。查引脚分配图，别硬配。
2. **有些引脚是"专用"的**：调试口（SWDIO/SWCLK）一配错，**调试器就再也连不上了**——这是最"窒息"的坑，改回来要靠按住复位或换启动方式。
3. **有些引脚上电时有特殊状态**（比如某些 BOOT 引脚），接线前查数据手册的"Pinouts and pin description"。
4. **5V 容忍**：不是所有引脚都容忍 5V，接传感器前查手册（否则可能烧脚）。

## 五、常见坑

1. **忘开 GPIO 时钟** → 配了完全没反应（2.3.4 第一大坑）。
2. **浮空输入当按键** → 电平乱跳，以为"板子有干扰"，其实是没配上下拉。
3. **开漏输出忘了外接上拉** → 只能拉低，**永远输出不了高电平**。
4. **PWM / 串口引脚配成普通推挽输出** → 外设接管不了这根脚，**引脚一点波形都没有**（3.4 经典坑）。
5. **同一根脚重复配置**：先按 GPIO 配、后又按复用配，或两个外设抢同一根脚。
6. **没配 `OSPEEDR`（速度）就用高速信号** → 波形上升沿变圆、通信出错；反之速度开太高也徒增干扰。**够用就好**。
