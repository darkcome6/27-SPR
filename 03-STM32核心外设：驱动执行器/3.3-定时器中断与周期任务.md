# 3.3 定时器中断与周期任务

> **一句话本质：定时器 = 一个会自己数数的硬件。数到点，它喊你一声（触发中断）。**
> **从此"时间"这件事，你交给硬件，而不是用 `for` 空转去等。**

---

## 一、为什么必须有定时器

回顾 2.3.2 那张表：

| 任务 | 新手写法 | 为什么不行 |
|---|---|---|
| 每 1 ms 跑一次控制 | `for` 空转等时间 | CPU 被锁死，别的活一秒都干不了；它还**不准**（主频、优化等级一变就废） |
| 隔 500 ms 服务一次看门狗 | `HAL_Delay(500)` | 阻塞，期间收不到任何数据、响应不了任何事件 |

**控制程序的心跳必须由硬件保证**——抖动是控制系统的天敌。
所以：**定时器 + 中断 = 周期任务的标准做法。**

---

## 二、基本原理（不深挖，够用就行）

```
   时钟源 ──> [预分频 PSC] ──> [计数器 CNT 自增] ──> 到达 [自动重装载 ARR]
                  ↑                                      │
              "把快时钟变慢"                          "数到了！"
                                                          │
                                          ┌───────────────┴────────────────┐
                                          ▼                                ▼
                                    产生中断（跑你的函数）            重新从 0 开始数
```

三个关键参数：

| 参数 | 作用 | 类比 |
|---|---|---|
| **时钟频率** | 定时器的"秒表精度"，来自时钟树（2.3.4） | 钟表走多快 |
| **PSC（预分频）** | 把时钟先除几 | 把秒表从"每 0.01 秒一跳"调成"每 1 秒一跳" |
| **ARR（重装载值）** | 数到多少算一轮 | 定几个倒计时 |

**算周期（唯一要记的公式）：**

$$
\text{溢出周期}=\frac{(\text{PSC}+1)\times(\text{ARR}+1)}{\text{定时器时钟频率}}
$$

**举例（STM32F4，定时器时钟 84 MHz，要 1 ms 一次）：**

- 取 `PSC = 83` → 84 MHz / 84 = **1 MHz**（每 1 μs 数一个）
- 取 `ARR = 999` → 数 1000 个 → **1000 μs = 1 ms** ✅

> 别背数字，**记住思路**：先用 PSC 把时钟调成"好算的整数"，再用 ARR 定周期。
> **实际频率以你板子的时钟配置为准**（CubeMX 里能直接看到）。

## 三、怎么让定时器真正跑起来：一个不能少的步骤

这是本节的重点——**"如何开启（配置）不同的时钟与中断"**：

| 步骤 | 代码 | 漏了会怎样 |
|---|---|---|
| ① **开外设时钟** | `__HAL_RCC_TIM3_CLK_ENABLE();` | 寄存器写不进去，**一点反应都没有** |
| ② **配中断优先级 + 使能中断通道** | `HAL_NVIC_SetPriority(...)` + `HAL_NVIC_EnableIRQ(...)` | **不会进中断**，主程序照跑，你等不到任何回调 |
| ③ **配 PSC / ARR** | `htim.Init.Prescaler / Period` | 周期不对 |
| ④ **启动 + 允许中断** | `HAL_TIM_Base_Start_IT(&htim);` | 定时器在跑，但**不产生中断**（安静的哑巴） |

**每一步都对应一个"静默失败"**——不报错、不崩溃，就是没现象。这就是嵌入式最磨人的地方。

## 四、完整代码骨架

```c
/* 1. 初始化：配定时器 + 中断 */
void Bsp_Timer_Init(void)
{
    __HAL_RCC_TIM3_CLK_ENABLE();                  /* ① 时钟 */

    htim3.Instance           = TIM3;
    htim3.Init.Prescaler     = 83;                /* 84MHz / 84 = 1MHz */
    htim3.Init.Period        = 999;               /* 1000 个 → 1ms */
    htim3.Init.CounterMode   = TIM_COUNTERMODE_UP;
    htim3.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
    HAL_TIM_Base_Init(&htim3);

    HAL_NVIC_SetPriority(TIM3_IRQn, 5, 0);        /* ② 优先级（数字越小越优先） */
    HAL_NVIC_EnableIRQ(TIM3_IRQn);                /*    使能中断通道 */

    HAL_TIM_Base_Start_IT(&htim3);                /* ④ 启动 + 允许中断 */
}
```

```c
/* 2. 中断入口：函数名必须和启动文件里的一致，否则永远不会被调用！ */
void TIM3_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim3);          /* 交给 HAL 清标志、分发（漏了会死循环进中断） */
}
```

```c
/* 3. 回调：HAL 提供的"弱函数"，你重写它就生效 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3) {        /* 多个定时器共用这个回调，必须判断是哪个 */
        /* ===== 这里是每 1 ms 执行一次的地方 ===== */
        g_tick_1ms++;
    }
}
```

### 三条铁律

1. **`TIM3_IRQHandler` 这个名字不能写错**（不同芯片可能在启动文件里叫别的名字）。
   写错了的现象是：**代码编译通过，但里面的东西从来不执行**。
2. **记得调用 `HAL_TIM_IRQHandler(&htim)`**（或自己清标志位）。
   漏了的现象是：**中断标志没被清除 → 中断被反复触发 → 主循环彻底不跑了**。
3. **回调里不许干重活**（下节详述）。

## 五、中断服务函数里该写什么（工程习惯，比语法重要）

**原则：中断里只做"必须立刻做的、极短的"事，其余甩给主循环。**

| 可以放 | 不要放 |
|---|---|
| 计数（`g_tick_1ms++`） | `HAL_Delay`（阻塞，等于自杀） |
| 置标志（`g_flag = 1`） | 大量 `printf`（串口慢，会拖垮整个系统） |
| 读一个寄存器 / 存一个值 | 复杂浮点运算、`for` 长循环 |
| 急停、关 PWM 这类**必须最快响应**的动作 | 写 Flash（毫秒级阻塞，3.3 之外的 2.3.3 也提过） |

**为什么？** 中断会打断一切。中断里花掉的每一微秒，都是整个系统的"卡顿"。
**最坏情况：中断比它自己的周期还长 → 系统直接瘫痪。**

### 推荐写法：中断"下单"，主循环"干活"

```c
volatile uint8_t g_flag_1ms = 0;      /* 中断与主循环共享 → 必须 volatile（2.2.8） */

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM3) {
        g_flag_1ms = 1;               /* 只置标志，干活的事交给主循环 */
    }
}

int main(void)
{
    /* ... 各种初始化 ... */
    while (1) {
        if (g_flag_1ms) {
            g_flag_1ms = 0;
            Chassis_Update();         /* 真正耗时的计算在这里做 */
        }
    }
}
```

（用 RTOS 时，对应的写法是 `osDelayUntil()` / `vTaskDelayUntil()` 做绝对周期等待，思路一样：**让出 CPU，不空转**。）

## 六、常见坑清单

1. **忘开外设时钟 / 忘 NVIC 使能 / 忘 Start_IT** → 三种不同的"静默失败"。
2. **中断函数名写错** → 从来不执行（编译还不报错）。
3. **忘了清中断标志** → 疯狂进中断，主循环卡死。
4. **PSC / ARR 算错** → 周期不对。**用示波器或 LED 实测**，别相信心算。
5. **回调里干重活** → 系统变慢、丢周期、通信丢包。
6. **周期计数变量类型太小**：1 ms 计数用 `uint16_t`，**65.5 秒后溢出**回到 0 → 定时逻辑突然错乱。用 `uint32_t`。
7. **多个定时器共用回调却不判断 `htim->Instance`** → 逻辑互相串。
8. **改了 CubeMX 里的时钟树但没重新生成代码** → 实际周期和公式对不上。

## 七、定时器还能干别的（预告 3.4）

**同一块硬件，配一配就能换工作**：

| 模式 | 用途 |
|---|---|
| 基本定时（本节） | 周期任务、计时 |
| **PWM 输出** | 控制电机 / 舵机（下一节） |
| 输入捕获 | 测脉宽、测超声波回波、读遥控信号 |
| 编码器接口 | 直接数电机编码器，不用中断去数 |
| 单脉冲模式 | 发一个精确定宽度的脉冲 |
