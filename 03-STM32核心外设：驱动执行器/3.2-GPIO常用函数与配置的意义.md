# 3.2 GPIO 常用函数与配置的意义

> **一句话本质：HAL 的 GPIO 函数，就是把 3.1 那几张寄存器表"翻译成人话"。**
> 你要理解的是**每个参数在拨哪个开关**，而不是记住函数名——**语法糖不用背，意义必须懂**。

---

## 一、一次完整的输出配置（骨架）

```c
__HAL_RCC_GPIOB_CLK_ENABLE();          /* ① 先开时钟！不开后面全白配（2.3.4） */

GPIO_InitTypeDef gpio = {0};           /* ② 结构体清零（2.2.5） */
gpio.Pin   = GPIO_PIN_8;               /*    哪根引脚 */
gpio.Mode  = GPIO_MODE_OUTPUT_PP;      /*    推挽输出 */
gpio.Pull  = GPIO_NOPULL;              /*    不要上下拉 */
gpio.Speed = GPIO_SPEED_FREQ_LOW;      /*    翻转速度：够用就好 */

HAL_GPIO_Init(GPIOB, &gpio);           /* ③ 传结构体地址：& 是指针（2.2.9） */
```

**每个字段都在拨一个开关**——这就是 3.1 讲的四个问题：

| 字段 | 拨的是哪个开关 | 决定什么 |
|---|---|---|
| `Pin` | —— | 操作**哪几根**引脚（多根用 `\|` 连起来） |
| `Mode` | `MODER` / `OTYPER` | 输入？输出？复用？模拟？推挽还是开漏？ |
| `Pull` | `PUPDR` | 要不要上拉 / 下拉 |
| `Speed` | `OSPEEDR` | 输出翻转有多快 |

> **为什么要设 `Speed`？** 引脚翻转太快会产生干扰（振铃、串扰）；太慢又跟不上高速信号。
> 所以 ST 给了几档：**普通 LED / 使能脚用 LOW 就够，SPI 这类高速信号才开 HIGH/VERY_HIGH。**
> 新手不用纠结：**默认 LOW**，出问题再往上调。

> **为什么要 `&gpio`？** 因为 HAL 要的是"结构体的地址"，不是把整个结构体拷贝进去（2.2.4 的"复印件"理论）。

## 二、最常用的四个函数

```c
/* 1. 置高（输出 1） */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_SET);

/* 2. 置低（输出 0） */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_RESET);

/* 3. 翻转（原来高变低、原来低变高）—— 闪灯神器 */
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_8);

/* 4. 读引脚电平 */
if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_SET) {
    /* 读到了高电平 */
}
```

就这四个。**剩下的全靠"知道自己在控制哪根脚"。**

---

## 三、它们背后动了哪个寄存器（理解这一层，就再也不怕换库）

| HAL 函数 | 真正干的事 |
|---|---|
| `HAL_GPIO_WritePin(..., SET)` | 往 `BSRR` 写 `1 << n` → 置位 |
| `HAL_GPIO_WritePin(..., RESET)` | 往 `BSRR` 写 `1 << (n+16)` → 复位 |
| `HAL_GPIO_TogglePin` | 读 `ODR` → 异或 → 写回 `ODR`（读-改-写） |
| `HAL_GPIO_ReadPin` | 读 `IDR` 的对应位 |

**为什么置位/复位要用 `BSRR` 而不是直接写 `ODR`？**
因为 `BSRR` 是"专门的置位/复位寄存器"：**写一次就够了，不需要"读-改-写"**，
所以它**天生是原子的**（不会被中断打断、也不会误改别的引脚）。
（对比 2.3.5 里 `ODR |= ...` 是三步操作。）

> **结论**：`HAL_GPIO_WritePin` 是安全的；自己手写 `GPIOB->ODR = ...` 才是危险的写法。

### 一次写多根引脚

```c
/* 同一状态的多根脚可以一次性写 */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0 | GPIO_PIN_1 | GPIO_PIN_2, GPIO_PIN_SET);

/* 不同状态必须分两次调用 */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_SET);
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_1, GPIO_PIN_RESET);
```

（"一次写多根"在写并口（如 LCD、数码管）时很有用。）

## 四、队里最常见的五类"翻车"

| 现象 | 真凶 | 怎么防 |
|---|---|---|
| 配了没反应，电平不动 | **忘了开 GPIO 时钟** | 初始化里第一行就是 `__HAL_RCC_GPIOx_CLK_ENABLE()` |
| 按键/传感器值乱跳 | **浮空输入**，没配上下拉 | 按接线选上拉或下拉（3.1） |
| 想操作的引脚没反应，**别的引脚动了** | `Pin` 写错、或引脚号算错 | 给引脚起宏名字：`#define LED_PIN GPIO_PIN_8`；用调试器看 `ODR` |
| 改了代码没效果 | 没 Build 就烧 / 没勾 Reset and Run | 3.0 那两条 |
| 读引脚在循环里"永远不变" | 没加 `volatile`，被编译器优化 | 中断/外部可能改的变量加 `volatile`（2.2.8） |

> **排查套路（背下来）**：
> **"引脚不动" → ① 时钟开了吗 ② 模式配成输出了吗 ③ 调试器里看 `ODR` 变了吗 ④ 硬件接线对吗。**
> 四步走完，问题一定在其中一步。

## 五、一个能直接用的模板

```c
/* gpio.h */
#ifndef GPIO_APP_H
#define GPIO_APP_H

#include "main.h"

#define LED_PORT    GPIOB
#define LED_PIN     GPIO_PIN_8

#define KEY_PORT    GPIOA
#define KEY_PIN     GPIO_PIN_0

void Bsp_Gpio_Init(void);
uint8_t Bsp_Key_IsPressed(void);

#endif
```

```c
/* gpio.c */
#include "gpio.h"

void Bsp_Gpio_Init(void)
{
    GPIO_InitTypeDef gpio = {0};

    __HAL_RCC_GPIOA_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();

    gpio.Pin   = LED_PIN;                    /* LED：推挽输出 */
    gpio.Mode  = GPIO_MODE_OUTPUT_PP;
    gpio.Pull  = GPIO_NOPULL;
    gpio.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(LED_PORT, &gpio);

    gpio.Pin  = KEY_PIN;                     /* 按键：上拉输入（按下接 GND） */
    gpio.Mode = GPIO_MODE_INPUT;
    gpio.Pull = GPIO_PULLUP;
    HAL_GPIO_Init(KEY_PORT, &gpio);

    HAL_GPIO_WritePin(LED_PORT, LED_PIN, GPIO_PIN_RESET);   /* 上电默认关灯 */
}

uint8_t Bsp_Key_IsPressed(void)
{
    return (HAL_GPIO_ReadPin(KEY_PORT, KEY_PIN) == GPIO_PIN_RESET) ? 1 : 0;
}
```

**注意这里的设计习惯**（比函数本身重要）：

1. **引脚号写成宏**，改名只改一处；换板子只改宏。
2. **`Bsp_` 前缀**：这一层是"板级支持"，业务代码不该出现 `GPIOB` 这类字眼。
3. **上电先给确定状态**（LED 灭、PWM 为 0）——**安全默认值**是机器人代码的底线。

## 六、别写 `HAL_Delay` 的那一天

```c
while (1) {
    HAL_GPIO_TogglePin(LED_PORT, LED_PIN);
    HAL_Delay(500);            /* 这 500 ms 里，CPU 什么都干不了 */
}
```

`HAL_Delay` 是**阻塞**的：它靠"空转等时间"，这期间 CPU 完全被占用。
**点灯演示可以用，控制程序里绝对不行**——正确做法是定时器周期任务（下一节 3.3）。
