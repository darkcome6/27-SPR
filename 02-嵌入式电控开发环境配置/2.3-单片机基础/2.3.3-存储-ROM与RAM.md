# 2.3.3 存储：ROM 与 RAM

> **一句话本质：Flash（ROM）是硬盘——掉电东西还在；SRAM（RAM）是桌面——一断电，全没了。**
>
> 弄清楚这一篇，你能解释一半以上的"玄学 bug"。

---

## 一、两张表讲清区别

| | **Flash / ROM** | **SRAM / RAM** |
|---|---|---|
| 里面放什么 | 程序代码、常量、要长期保存的参数 | 变量、栈、堆 |
| 掉电后 | **保留** | **全部丢失** |
| 速度 | 慢一些 | 快（常 1~2 个时钟周期就能读写） |
| 写起来 | 麻烦：要按扇区擦除，且有寿命（约 1 万 ~ 10 万次） | 随便写 |
| 容量 | 大（F4 典型 512 KB ~ 1 MB） | **小**（F4 典型 128 ~ 192 KB） |
| 电脑里的类比 | 硬盘 / 固态 | 内存条 |

**注意最后一行的量级差：RAM 通常只有 Flash 的几分之一到十分之一。**
"嵌入式要省内存"，省的其实是 **RAM**。

---

## 二、代码和变量分别在哪儿（呼应 2.2.7）

链接脚本给 Flash 和 RAM 各划了一块地盘（STM32 的惯例地址）：

```ld
FLASH : ORIGIN = 0x08000000, LENGTH = 512K    /* 程序住这儿 */
RAM   : ORIGIN = 0x20000000, LENGTH = 128K    /* 变量住这儿 */
```

于是：

| 东西 | 住在哪 | 说明 |
|---|---|---|
| 代码、常量（`.text`） | Flash | 只读，改不了 |
| 有初值的全局变量（`.data`） | **初值在 Flash，上电时拷到 RAM** | 所以能改、掉了就没了 |
| 没初值 / 初值为 0 的全局变量（`.bss`） | RAM | 上电时启动文件整块清零 |
| 局部变量、函数调用现场（栈） | RAM | **没人替它清零，值是随机的** |
| `malloc` 出来的（堆） | RAM | 单片机里尽量别用 |

**回看 2.2.3 那条坑**（"局部变量没初始化，值是随机的"）：现在你知道为什么了——它躺在栈上，启动文件只清 `.bss`，不碰栈。

---

## 三、栈：最容易被忽略、也最爱出事的地方

**栈就是 RAM 里的一块"临时工位"**：

```c
void f(void)
{
    int16_t buf[100];      /* 100 × 2 = 200 字节，全从栈上要 */
    /* 函数返回时自动"归还" */
}
```

栈的空间是**有限**的（在链接脚本里指定，通常几 KB 到几十 KB）。**栈溢出**会发生什么？

```
栈生长方向 ↓
┌──────────────┐
│   栈空间      │
├──────────────┤ ← 越界了！
│  别的变量     │  ← 被踩坏 → 表现出"变量自己乱变"的玄学 bug
└──────────────┘
```

**典型症状**：改一个不相关的变量，另一个变量的值就变了；加一行打印就"好了"；函数一深就重启。

**保命做法：**

1. **大数组别放局部变量**：局部数组占栈，全局 / `static` 数组占 `.bss`（RAM 的另一块，不占栈）。
   ```c
   void f(void)
   {
       static uint8_t buf[512];   /* 不占栈，程序启动就分配好 */
   }
   ```
2. **别递归**（单片机里递归基本等于自杀）。
3. RAM 紧张时：看 `.map` 文件，谁占得多一目了然（2.2.7）。

---

## 四、想"掉电不丢"怎么办

普通变量放在 RAM，**一断电就归零**。要让参数记住（比如 PID 参数、机械零点），必须**写进 Flash**。

三条必须知道的规矩：

1. **Flash 不能随便写**：要先擦除整个扇区（通常几 KB 一块），擦除期间 CPU 会阻塞。
2. **有寿命**：约 1 万 ~ 10 万次擦写。**绝对不能在控制循环里写**（一天就能写废）。
3. **写完校验**：掉电发生在写一半时，数据可能损坏 → 简单做法是存两份 + 一个校验值。

（队里常见的做法：只在"参数被修改后"写一次，不在周期任务里写。）

---

## 五、常见坑（逐条对号）

1. **大数组 / 大结构体放局部变量** → 栈溢出 → 玄学 bug（最经典）。
2. **以为随便一个变量都能"保存"** → 重启就没了。
3. **在 1 ms 任务里写 Flash** → 卡顿 + 寿命耗尽。
4. **`int16_t` 数组开得太大**：512 个元素就 1 KB，STM32F103 只有 20 KB RAM——**先算容量，再开数组**。
5. **把"内存"和"外存"的需求搞混**：运行时要用的放 RAM，要长期保留的放 Flash。
