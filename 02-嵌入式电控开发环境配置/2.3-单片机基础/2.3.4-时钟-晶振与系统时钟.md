# 2.3.4 时钟信号：晶振与系统时钟

> **一句话本质：时钟是单片机的心跳。每"跳"一下，电路才允许往前走一步。**
> 心跳多快，就是**主频**多高。

---

## 一、为什么需要时钟

数字电路不像人，它不知道"下一步"该什么时候发生。时钟就是发号施令的节拍器：

- **没时钟**：整块芯片处于静止，一条指令都不执行。
- **时钟太慢**：活儿干不完，控制周期做不长。
- **时钟不准 / 抖动**：串口波特率、定时器周期、采样时刻全都会错——**通信乱码、控制抖动，很多时候根源在时钟**。

所以：**上电第一件事就是配置时钟，然后才是配置外设。**（CubeMX 生成的代码也是这个顺序。）

---

## 二、晶振：最准的"节拍器"

**晶振（石英晶体振荡器）** 利用石英晶体的压电效应，产生**极其稳定**的振荡频率。

| | 晶振（外部） | 芯片内部 RC 振荡器 |
|---|---|---|
| 精度 | 很高（±10~50 ppm，即百万分之几十） | 差（可能差百分之几） |
| 成本 | 要多焊一个元件 | 白送，在芯片里 |
| 常见用途 | 主时钟来源 | 上电默认时钟、备用 |

**为什么不准不行？** 串口通信按"每秒多少位"约定时间。两边时钟差 3%，数据就可能采样错位 → **乱码**。
（所以：能上外部晶振就上外部晶振。）

---

## 三、STM32 的时钟源（一张表记牢）

| 时钟源 | 类型 | 典型频率 | 用途 |
|---|---|---|---|
| **HSI** | 内部 RC | 8 / 16 MHz | 上电默认、无晶振也能跑（精度差） |
| **HSE** | **外部晶振** | 8 MHz（常见） | 主力时钟来源，精度高 |
| **PLL** | 倍频器 | 8 MHz × N | 把低频"放大"成高频，得到主频 |
| **LSE** | 外部晶振 | 32.768 kHz | 给 RTC 走时 |
| **LSI** | 内部 RC | ≈ 32 kHz | 独立看门狗 |

> **彩蛋：为什么 RTC 用 32.768 kHz？**
> 32768 = 2¹⁵。它只要**连续 15 次二分频**，就正好得到 1 Hz（每秒一跳）——这就是时钟手表的原理。

---

## 四、时钟树：从晶振到 168 MHz

```
  HSE 8 MHz ──> PLL（倍频 ×168）──> SYSCLK 168 MHz（主频）
                                        │
                     ┌──────────────────┼──────────────────┐
                     ▼                  ▼                  ▼
                  AHB 总线            APB1 总线          APB2 总线
                （高速，168MHz）    （低速，42MHz）    （高速，84MHz）
                     │                  │                  │
                    SRAM / DMA        UART / I2C / TIM    GPIO / SPI / ADC
```

三句话读懂：

1. **HSE** 提供基础频率（8 MHz）。
2. **PLL 倍频**把它放大到 168 MHz —— **这就是主频**。
3. **分频**再送给不同总线上的外设：低速外设（如 I2C）不需要那么快，分给它们低频率更稳、更省电。

**CubeMX 里那张 `Clock Configuration` 图，画的就是这条路径。** 一定要自己点开看一遍。

> 外设的工作频率会**直接影响它的行为**：串口波特率、定时器计数频率、SPI 速度，都从这条链上"分"出来。
> 所以"时钟配错了 → 外设表现全错"，这是非常常见的现场事故。

---

## 五、最经典的坑：忘了开外设时钟

STM32 为了省电，**所有外设的时钟默认是关着的**。你要用哪个外设，必须先开它的时钟：

```c
__HAL_RCC_GPIOB_CLK_ENABLE();      /* 开 GPIOB 的时钟 —— 漏了这句，后面全白配 */
__HAL_RCC_USART1_CLK_ENABLE();
__HAL_RCC_TIM3_CLK_ENABLE();
```

**症状**：代码看起来一点没错，编译器也不报错，可引脚就是不动 / 串口就是没输出。
**这是新手第一大坑，没有之一。** 出现"全对但没现象"，第一反应就是查时钟。

---

## 六、其他常见坑

1. **改了主频，却没同步更新依赖它的东西**
   延时是按主频算的（`HAL_Delay` 依赖 `SystemCoreClock`），时钟改了、宏没改，延时就不再是 1 ms。串口波特率同理。
2. **晶振不起振 → 程序根本不跑**
   现象：烧录正常，但上电毫无反应（连灯都不闪）。先查晶振是否焊好、负载电容是否匹配，或者先用 HSI 启动试试。
3. **看门狗时钟源搞错**：IWDG 用 LSI，主时钟动它也不受影响——反过来说，"时钟乱了它照样复位你"，这是特性不是 bug。
4. **以为"时钟"只是给 CPU 用的**：外设、总线、DMA 都吃时钟，缺一处就有一处不动。
