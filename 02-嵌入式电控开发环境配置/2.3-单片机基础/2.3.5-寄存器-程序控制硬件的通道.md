# 2.3.5 寄存器：程序控制硬件的唯一通道

> **一句话本质：寄存器是一扇窗——你往里写的每一位，直接对应硬件上的一根开关。**
>
> CPU 不会"指挥"硬件，它只会**写寄存器**。除此之外没有第二条路。

---

## 一、从"地址"看整块芯片

芯片把所有"你能操作的东西"编成一整块连续的地址，这叫 **Memory Map（地址映射）**：

| 区域 | 起始地址（STM32 惯例） | 里面是什么 |
|---|---|---|
| Flash | `0x0800 0000` | 你的程序 |
| SRAM | `0x2000 0000` | 变量、栈 |
| **外设** | `0x4000 0000` 起 | GPIO / UART / TIM / ADC… 的寄存器 |
| 内核私有 | `0xE000 0000` 起 | 中断控制器、系统滴答等 |

**关键认识：外设寄存器和内存，在 CPU 眼里是同一种东西——都是"某个地址上的数据"。**
所以"控制硬件"和"写变量"在指令层面是同一件事（这就是 2.2.1 那行"魔法代码"能点亮 LED 的原因）。

---

## 二、一个外设 = 一组寄存器

每个外设占一小片地址，里面按**偏移量**排开若干寄存器。以 GPIOB 为例：

| 偏移 | 寄存器 | 管什么 |
|---|---|---|
| `0x00` | `MODER` | 每个引脚是**输入还是输出** |
| `0x04` | `OTYPER` | 推挽 / 开漏 |
| `0x0C` | `PUPDR` | 要不要上拉 / 下拉 |
| `0x10` | `IDR` | **读**引脚当前电平 |
| `0x14` | `ODR` | **写**输出电平 |

于是 GPIOB 的 `ODR` 寄存器地址 = 基地址 + 偏移：

```
0x40020400  +  0x14  =  0x40020414
```

**所有寄存器的地址都是这么算出来的**——不是背下来的，是"基地址 + 偏移"查表得来的。

## 三、同一件事的三种写法

```c
/* ① 最原始：绝对地址 + 指针（2.2.9 那行的真身） */
*(volatile uint32_t *)0x40020414 |= (1U << 8);      /* 把 PB8 置高 */

/* ② CMSIS：ST 官方头文件把基地址定义成结构体指针，好读多了 */
GPIOB->ODR |= (1U << 8);

/* ③ HAL 库：再包一层，用人话描述 */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_SET);
```

**这三种写法在芯片里干的事一模一样：往同一个地址、写同一个值。**

由此得到本节最重要的一条结论：

> **库函数不是魔法，它只是"帮你把寄存器写对"的一层包装。**
> 所以：**看不懂某个库函数时，去查它写了哪个寄存器，你就懂了。**
> （这也是为什么我们要先讲寄存器，再讲怎么用 HAL。）

## 四、位操作三件套（嵌入式肌肉记忆）

寄存器常常是"一个 32 位里塞了 32 根开关"。为了只动其中一根，用位运算：

```c
REG |=  (1U << n);     /* 把第 n 位置 1  —— 打开这根开关 */
REG &= ~(1U << n);     /* 把第 n 位清 0  —— 关掉这根开关 */
REG ^=  (1U << n);     /* 翻转第 n 位 */

if (REG & (1U << n))   /* 读第 n 位：非 0 就是 1 */
```

**为什么不用 `REG = (1U << 8);` 直接赋值？**
因为那是"整排开关一起拨"：你只想开 PB8，结果顺手把别人正在用的位全清零了。
（2.2.1 里为了简单先这么写，是加了前提的；实际工程里一律用 `|=` / `&= ~`。）

## 五、寄存器怎么查：参考手册

**别从头读手册**（几千页）。按这个路径查：

1. 打开**参考手册**（Reference Manual，STM32F4 是 `RM0090` 这类），不是数据手册。
2. 找到外设章节（如 `GPIO`）。
3. 先看**功能框图**：这外设由哪几块组成、信号怎么流。
4. 再看**寄存器表**：每个位叫什么、0/1 各代表什么。
5. 需要时序时，看章节后面的**波形图**。

**举例**：想知道"怎么把 PB8 配成输出模式"，就查 `GPIOx_MODER`——每个引脚占 2 位，`01` 表示"通用输出模式"，PB8 对应第 16、17 位。

## 六、常见坑

1. **漏了 `volatile`**
   ```c
   #define REG (*(volatile uint32_t *)0x40020414)   /* 少 volatile 会被编译器"优化掉"（2.2.8） */
   ```
2. **读-改-写不是原子的**：`REG |= (1U << n)` 实际是"读 → 改 → 写"三步。若中途被中断打断、且中断也改了同一个寄存器，可能丢失更新。
3. **位号 / 偏移算错**：手册里说的是"第几位"，不是"第几个引脚"——`PB8` 是 `1U << 8`，不是 `1U << 1`。
4. **忘了先开外设时钟**：寄存器写下去没反应（2.3.4 第一大坑）。
5. **直接 `REG = 0x...` 覆盖别人**。
