# 2.2.2 c 文件与 h 文件的关系

> **一句话本质：`.h` 是目录（声明），`.c` 是正文（实现）。**
> 别人要用你的功能，只需要看"目录"，不需要看"正文"。

---

## 一、先记住一个反直觉的事实

**`#include` 不是"引用"，而是"复制粘贴"。**

编译之前有个**预处理**阶段，它会把 `#include "motor.h"` 这一行**原地删掉，换成 `motor.h` 的全部内容**。
所以：

- `.h` 里写什么，就会被**原样塞进每一个** include 它的 `.c` 文件里。
- `.h` 里不该放的东西（函数体、变量定义）会因此被复制多份 → 链接时报 `multiple definition`。

（预处理还会做 `#define` 文本替换、`#if` 条件裁剪，见 2.2.8。）

---

## 二、为什么要拆成两个文件

因为**编译是以 `.c` 为单位的**：

```
motor.c ──编译──> motor.o ─┐
main.c  ──编译──> main.o  ─┼──链接──> firmware.elf ──> firmware.bin
uart.c  ──编译──> uart.o  ─┘
```

`main.c` 编译的时候，**根本没见过 `Motor_SetSpeed` 的函数体**。
它只需要知道一件事："有这么个函数，参数长这样，返回这个东西"——这个信息就在 `.h` 里。
真正的函数体由**链接器**在最后一步去别的 `.o` 里找到地址、接上。

这就是**声明（declaration）与定义（definition）**的区别：

| | 声明 | 定义 |
|---|---|---|
| 作用 | 告诉编译器"有这个东西，长这样" | 真正分配内存 / 生成代码 |
| 例子 | `void Motor_SetSpeed(uint8_t id, int16_t speed);` | 带 `{ ... }` 的那个函数本体 |
| 位置 | 放 `.h` | 放 `.c` |

## 三、一个最小例子：拆出电机模块

```c
/* ---------------- motor.h ---------------- */
#ifndef MOTOR_H          /* 头文件保护，见 2.2.8 */
#define MOTOR_H

#define MOTOR_NUM        4               /* 宏：纯文本替换 */
#define MOTOR_MAX_SPEED  1000

typedef struct {                         /* 类型定义：谁要用谁得看见 */
    int16_t speed;
} Motor_t;

extern Motor_t motor[MOTOR_NUM];         /* 变量声明：定义在 motor.c 里 */

void Motor_SetSpeed(uint8_t id, int16_t speed);   /* 函数声明 */
int16_t Motor_GetSpeed(uint8_t id);

#endif
```

```c
/* ---------------- motor.c ---------------- */
#include "motor.h"      /* 必须包含自己的头，保证声明与定义一致 */

Motor_t motor[MOTOR_NUM];    /* 真正的定义：这里才分配内存 */

void Motor_SetSpeed(uint8_t id, int16_t speed)
{
    if (id >= MOTOR_NUM) return;             /* 边界检查：C 不会替你拦 */
    if (speed > MOTOR_MAX_SPEED)  speed =  MOTOR_MAX_SPEED;
    if (speed < -MOTOR_MAX_SPEED) speed = -MOTOR_MAX_SPEED;

    motor[id].speed = speed;
    /* 真正写寄存器 / 发 CAN 报文 ... */
}

int16_t Motor_GetSpeed(uint8_t id)
{
    return (id < MOTOR_NUM) ? motor[id].speed : 0;
}
```

```c
/* ---------------- main.c ---------------- */
#include "motor.h"      /* 只要"目录"，不要"正文" */

int main(void)
{
    Motor_SetSpeed(0, 500);
    return 0;
}
```

## 四、什么东西该放哪

| 放 `.h`（给别人看的目录） | 放 `.c`（自己的实现） |
|---|---|
| 函数声明 | 函数体 |
| `#define` 宏、常量 | 内部用的 `static` 变量 |
| `typedef`、结构体、枚举定义 | —— |
| `extern` 变量声明 | **变量定义**（`Motor_t motor[4];`） |

一句话判断法：**"这行代码会占用内存、或会产生机器码吗？"**
会 → 放 `.c`；只是"打个招呼" → 放 `.h`。

---

## 五、常见坑

1. **在 `.h` 里写函数体 / 变量定义**
   → 每个 include 它的 `.c` 都生成一份 → 链接报 `multiple definition of ...`
2. **`.c` 忘了 include 自己的 `.h`**
   → 声明和定义不一致，**编译器不会报错**，出错时在别的文件里报，极其难查。（养成"`.c` 第一行就 include 自己的 `.h`"的习惯。）
3. **头文件互相 include**
   → 无限套娃。靠头文件保护宏兜住（见 2.2.8）。
4. **把 `.h` 当"公共变量堆放处"**
   → 所有人 include 就拿到所有全局变量，代码越写越乱（07 章会专门整治）。
