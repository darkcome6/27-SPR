# 2.2.8 进阶 · 预处理与常用修饰词

> **一句话本质：这些"看起来莫名其妙的关键字"，每一个都在回答一个具体问题。**
> 看不懂它们，不是因为难，是因为没人告诉你它在解决什么。

---

## 一、`#ifndef` / `#define` / `#endif`：头文件保护

### 它解决什么问题

`#include` 是**文本复制**（2.2.2）。如果一个 `.h` 被复制了两次，里面的结构体定义、宏就出现了两次 → 编译报 `redefinition`。

什么时候会被包含两次？非常常见：

```
main.c
 ├── #include "chassis.h"
 │        └── #include "motor.h"      ← 第一次
 └── #include "motor.h"              ← 第二次，重复了！
```

### 怎么写

```c
/* ---------------- motor.h ---------------- */
#ifndef MOTOR_H          /* 如果 MOTOR_H 这个"开关"还没被定义过 */
#define MOTOR_H          /* 那就定义它，并往下走 */

/* …… 头文件的全部内容 …… */

#endif                   /* 结束 */
```

**机制**：第一次包含时，`MOTOR_H` 未定义 → 定义它 → 内容被插进来。
第二次包含时，`MOTOR_H` 已经定义了 → `#ifndef` 判断为假 → **中间整块内容被跳过**。

这就是"保护宏"。等价写法（现代编译器都支持，更短）：

```c
#pragma once
```

> 规矩：**队里每个 `.h` 的第一件事就是写保护宏**（或者 `#pragma once`）。这不是风格问题，是硬性要求。
> 宏名惯例用文件名大写加下划线，别撞车。

## 二、`__packed`：取消结构体的"对齐填充"

### 它解决什么问题

编译器为了让 CPU 高效访问，会在结构体成员之间**偷偷插空字节**（对齐）：

```c
typedef struct {
    uint8_t  a;      /* 偏移 0 */
    /* 这里被插了 3 个空字节 */
    uint32_t b;      /* 偏移 4 */
    uint16_t c;      /* 偏移 8 */
    /* 末尾又补了 2 个 */
} S;                  /* sizeof(S) == 12，而 1+4+2 == 7 */
```

平时无所谓；**一旦这个结构体是用来"对接通信协议"的，就出大事**：
上位机发来 7 个字节，你按 12 字节的结构体去解析 → **字段全部错位，收到的数据是垃圾**。

### 怎么写

```c
typedef struct __attribute__((packed)) {   /* GCC / arm-none-eabi-gcc 写法 */
    uint8_t  a;
    uint32_t b;
    uint16_t c;
} S;                                       /* sizeof(S) == 7 */

/* Keil（armcc）写法：__packed typedef struct { ... } S; 或 #pragma pack(1) */
```

**一句话理解**：`packed` = 让内存布局和你画的表格**一模一样**，一个空字节都不许插。

### 使用注意

- 只在**协议报文、Flash 里的参数结构**这类"必须按字节严格对齐"的地方用。
- 打包后成员地址可能"不对齐"，某些内核/指令访问非对齐地址会变慢甚至异常 → **别乱用，更别用它去装普通业务结构体**。
- 打包结构体的**成员越界访问**（比如直接取结构体里某个成员的指针）要小心，编译器只保证布局，不保证你能安全地单独访问某个成员。

## 三、`extern`：跨文件共享一个变量

### 它解决什么问题

`.c` 是分别编译的，但**变量名字在链接时必须是唯一的**（2.2.7）。
那么"我在 `main.c` 里想用 `chassis.c` 里的变量"该怎么办？

**办法：一个地方"真定义"，其他地方"打个招呼"。**

```c
/* chassis.c —— 真正的定义：这里分配内存 */
Chassis_t chassis;

/* chassis.h —— 声明：告诉别人"有这么个变量，定义在别处" */
extern Chassis_t chassis;

/* main.c */
#include "chassis.h"
chassis.target[0] = 500;      /* 能用，内存是 chassis.c 里那份 */
```

**机制**：`extern` 只产生一个"记号"，不占内存。链接器看到 `main.o` 里有对 `chassis` 的引用，会去别的 `.o` 里找它的定义，把地址填上（找不到就是 `undefined reference`）。

### 最常见的错误

```c
/* chassis.h —— 错的！ */
Chassis_t chassis;              /* 每个 include 它的 .c 都生成一份 → multiple definition */
Chassis_t chassis = {0};        /* 更错，带初值的一定是"定义" */
```

**判断法（同 2.2.2）：会产生内存/机器码的 → 放 `.c`；只是"打个招呼"的 → 加 `extern` 放 `.h`。**

> 提醒：`extern` 用多了就是"全局变量满天飞"，代码会越来越难维护。
> 现阶段先看懂它；怎么收口见 07 章（模块化与接口设计）。

## 四、顺带认识三个你会天天见到的词

| 关键词 | 作用（各一句） | 队里什么时候见 |
|---|---|---|
| `static` | 修饰函数 → **只在本文档可见**（别的文件 `extern` 不到）；修饰函数内变量 → 只初始化一次，**值在多次调用间保留** | 模块内部的私有函数；记录"上次的值" |
| `const` | **只读**，编译器帮你拦写操作；常量和查表数据放 Flash，省 RAM | 常量表、参数上限 |
| `volatile` | 告诉编译器：**这个值可能被外部（中断 / 另一个线程 / 硬件寄存器）改变，每次都必须真的去读，不许优化掉** | 中断里改的全局变量；直接访问寄存器 |

### `volatile` 为什么这么重要（必读）

```c
volatile uint8_t flag = 0;

void EXTI_IRQHandler(void) { flag = 1; }    /* 中断里改 */

int main(void)
{
    while (flag == 0) { }                   /* 等中断置位 */
}
```

如果 `flag` **没加** `volatile`：编译器发现循环里没人改 `flag`，直接把它优化成 `while (1)` ——**中断再怎么置位都没用**，程序卡死。
加了 `volatile`，编译器每一轮都老老实实去内存里读。

> 一句话规矩：**中断/其它线程会改的变量，加 `volatile`；直接映射寄存器的指针，加 `volatile`。**
> （寄存器指针的正确写法：`#define REG (*(volatile uint32_t *)0x40020414)`，对照 2.2.1。）
