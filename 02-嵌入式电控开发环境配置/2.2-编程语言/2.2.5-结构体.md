# 2.2.5 结构体

> **一句话本质：把一堆"本来散的、但说的是同一件事"的变量，捆成一个包。**
>
> 队友的代码里，**每个线程都有一个大结构体**——就是这一节的东西。

---

## 一、为什么要捆

不用结构体的写法：

```c
float   pid0_kp, pid0_ki, pid0_kd, pid0_err;
float   pid1_kp, pid1_ki, pid1_kd, pid1_err;
int16_t motor0_target, motor0_actual, motor0_output;
int16_t motor1_target, motor1_actual, motor1_output;
/* ……4 个轮子就是 30 多个名字，改名、加参数都是灾难 */
```

用结构体：

```c
typedef struct {
    float kp, ki, kd;      /* PID 参数 */
    float err;             /* 上次误差 */
    float out;             /* 输出 */
} PID_t;

typedef struct {
    int16_t target;        /* 输入：目标转速 */
    int16_t actual;        /* 输入：实际转速 */
    PID_t   pid;           /* 嵌套：每个轮子一个 PID */
    int16_t output;        /* 输出：给电机的值 */
} Wheel_t;

Wheel_t wheel[4];          /* 4 个轮子，一个数组搞定 */
```

**信息量没变，但组织方式变了**——这才是结构体的价值：不是省字，是**让"一个东西"在代码里以一个整体的形式存在**。

---

## 二、语法四件事

### 1. 定义类型（`typedef struct`）

```c
typedef struct {
    int16_t target;
    int16_t actual;
} Wheel_t;
```

`typedef` 的作用：给这个类型起个短名字，以后写 `Wheel_t w;` 而不是 `struct Wheel w;`。
**放 `.h` 里**，因为多个 `.c` 都要用（见 2.2.2）。

### 2. 定义变量 + 初始化

```c
Wheel_t w1;                  /* 局部变量：成员值随机！ */
Wheel_t w2 = {0};            /* 全部成员清零：推荐 */
Wheel_t w3 = {500, 480};     /* 按顺序给初值（容易错位，不推荐） */
Wheel_t w4 = { .target = 500 };   /* 指定成员初始化：最清晰 */
```

> 全局变量默认就是 0，但**写 `= {0}` 是明确表达"我要它从 0 开始"**——这是好习惯。

### 3. 成员赋值：用 `.`

```c
wheel[0].target = 500;
wheel[0].pid.kp = 1.2f;      /* 嵌套：一层一层点下去 */
```

### 4. 嵌套

结构体可以套结构体、套数组，也可以被数组装着：

```
Wheel_t wheel[4]        →  wheel[2].pid.ki
Chassis_t chassis       →  chassis.wheel[1].output
```

**点号链就是在"描述路径"**：先找到车，第 2 个轮子，它的 PID 的 ki 参数。

---

## 三、队里最重要的用法：线程的大结构体

一个控制线程（任务）里，通常有一个"全局唯一"的大结构体，装着**这个线程要用到的所有状态**：

```c
/* chassis.h */
typedef struct {
    /* ---- 输入 ---- */
    int16_t  target[4];       /* 目标转速（来自遥控/上位机） */
    int16_t  actual[4];       /* 实际转速（来自编码器） */
    /* ---- 中间量 ---- */
    PID_t    pid[4];          /* 每个轮子一份 PID 状态 */
    /* ---- 输出 ---- */
    int16_t  output[4];       /* 最终 PWM / 电流值 */
    /* ---- 自身状态 ---- */
    uint8_t  enable;          /* 线程开关 */
    uint32_t tick;            /* 周期计数 */
} Chassis_t;

extern Chassis_t chassis;     /* 声明（定义在 chassis.c） */
```

打包成一个大结构体的三个好处：

1. **命名不再打架**：不同模块里都有 `target`，`chassis.target` 和 `gimbal.target` 一眼分清。
2. **调试器里一眼看全**：Ozone / 调试窗口展开 `chassis`，整个线程的状态全在里面。
3. **整体清零/复位**：`memset(&chassis, 0, sizeof(chassis));` 一行回到初始状态。

```c
/* chassis.c */
Chassis_t chassis;            /* 真正的定义，内存在这里分配 */
```

> 新手最容易困惑的一件事：**为什么这个结构体是全局的？**
> 因为它在多个文件、多个函数里被读写——它是这个线程的"共享黑板"。代价是**谁都能改它**，
> 所以要靠约定（谁能写、谁只能读）来管理，07 章会讲怎么收口。

## 四、两个必须知道的细节

### 1. `sizeof` 不等于成员之和

编译器为了让 CPU **高效访问**，会在成员之间插"空字节"（对齐填充）：

```c
typedef struct {
    uint8_t  a;
    uint32_t b;    /* 为了对齐，a 后面可能被塞 3 个空字节 */
    uint16_t c;
} S;               /* sizeof(S) 可能是 12，而不是 1+4+2=7 */
```

平时**不用管**；但**和通信协议对齐时**就致命了（上位机给你 7 字节，你这边结构体 12 字节）。
解决办法是"打包"：`__attribute__((packed))` / `__packed`，见 2.2.8。

### 2. 结构体传参是"整份拷贝"

```c
void f(Chassis_t c);       /* 把整个结构体复制一份进去：又慢又占栈 */
void f(Chassis_t *c);      /* 只传地址：推荐（见 2.2.9） */
```

大结构体一律**传指针**，函数里用 `c->target[0]` 访问。
