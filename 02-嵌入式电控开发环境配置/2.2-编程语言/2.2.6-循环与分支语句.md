# 2.2.6 for / while / switch case

> **一句话本质：让电脑"重复做"，以及"选择做"。**
>
> 语法只有几行，坑却最多——这一篇的重点在最后两节的坑上。

---

## 一、`for`：次数已知的重复

```c
#define MOTOR_NUM 4

for (uint8_t i = 0; i < MOTOR_NUM; i++) {   /* 初始化 ; 条件 ; 步进 */
    output[i] = target[i] - actual[i];
}
```

执行顺序：**初始化 → 判断条件 → 循环体 → 步进 → 再判断**（判断是真才继续）。

`for` 最适合"**遍历一排数据**"：数组、缓冲区、4 个轮子、8 路舵机。

> 为什么写 `i < 4` 而不是 `i <= 4`？
> 4 个元素的下标是 `0 1 2 3`，`<= 4` 会让 `i` 取到 4 —— **越界访问别人的内存**。这是 C 最高频的 bug 之一。

---

## 二、`while`：条件满足就一直做

```c
while (flag == 0) {      /* 条件成立就进循环体 */
    /* ... */
}
```

**队里最常见的一种 `while`：无限循环**

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    /* 各种初始化 ... */

    while (1) {                  /* 裸机的主循环：程序"活着"就靠它 */
        Chassis_Update();
        Led_Toggle();
    }
}
```

要点：**`main` 里的 `while (1)` 绝不能退出**。单片机没有操作系统替你收尾，循环一退出就是空转/跑飞。
（用 RTOS 时，每个线程内部同样是一个死循环，只是外面包了一层任务调度。）

```c
while (1) {
    /* 一个周期要干的事 */
    HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
    HAL_Delay(500);        /* 一定要有"让出时间"的动作 */
}
```

**`while (1)` 里不放任何延时/让出，会怎样？**
在裸机上没事（但也意味着其它"分时"逻辑没法跑）；在 RTOS 里会把同一优先级的所有任务**饿死**——所以在任务里必须 `osDelay()` / `vTaskDelay()`。

### `do { } while (...)`：至少执行一次

```c
do {
    key = Key_Scan();
} while (key == 0);      /* 先执行，再判断 */
```
适合"先做，再决定要不要接着做"的场景。

## 三、`switch case`：多分支选择

```c
switch (state) {
    case STATE_IDLE:
        output = 0;
        break;                 /* ← 没有它，会继续往下执行！ */
    case STATE_RUN:
        output = pid_out;
        break;
    case STATE_ESTOP:
        output = 0;
        break;
    default:                   /* 兜底：所有 case 都没命中时走这里 */
        output = 0;
        break;
}
```

**`break` 的作用：立即跳出整个 `switch`。**
忘了写 → **穿透（fall through）**：从命中的 `case` 一路往下执行到底。

穿透有时是**故意**的：

```c
switch (mode) {
    case MODE_A:
    case MODE_B:            /* A 和 B 走同一段代码：故意不写 break */
        Common_Init();
        break;
    default: break;
}
```
但"不小心忘写"的穿透是 bug——**除了故意共用，每个 `case` 后面都写 `break`。**

### 什么时候用 `switch`，什么时候用 `if-else if`

| 判据 | 选择 |
|---|---|
| 判一个变量的**具体取值**（等于几） | `switch`，一眼看清所有分支 |
| 判**范围 / 多个条件组合**（`> 100 && flag`） | `if-else if` |

## 四、状态机骨架（机器人里到处都是）

```c
typedef enum {
    STATE_IDLE = 0,
    STATE_RUN,
    STATE_ESTOP
} State_t;

static State_t state = STATE_IDLE;

void Chassis_Task(void)
{
    switch (state) {
        case STATE_IDLE:
            if (cmd_start) {
                state = STATE_RUN;          /* 只改状态，不干重活 */
            }
            break;

        case STATE_RUN:
            Chassis_Calc(target, actual, output, MOTOR_NUM);
            if (cmd_stop)   state = STATE_IDLE;
            break;

        case STATE_ESTOP:
            output[0] = output[1] = output[2] = output[3] = 0;
            if (cmd_reset)  state = STATE_IDLE;
            break;

        default:
            state = STATE_IDLE;             /* 兜底：永远别让自己卡在未知状态 */
            break;
    }
}
```

这个模式记牢：**每一轮只判断"我该在哪个状态、要不要切"，不在 `switch` 里写长逻辑。**
写出这个骨架，你的代码就已经赢过一半新手了。

## 五、高频坑（逐条对照自己的代码）

1. **`i <= 长度`** → 越界。
2. **`if (x = 1)`** → 赋值当判断，永远为真。想比较就写 `==`（顺手把 `if (1 == x)` 当习惯也行）。
3. **浮点数直接比相等** → `if (a == 1.0f)` 基本永远不成立，浮点是近似值。要比较就写 `fabs(a - 1.0f) < 0.001f`。
4. **`while (1)` 里没有延时/让步** → 在 RTOS 里饿死别人（见上）。
5. **`break` 用错地方**：`switch` 里的 `break` 只跳出 `switch`，不会跳出外面的 `for`；要从两层循环里跳出来，用 `flag` 变量或 `goto`（队里不鼓励 `goto`）。
6. **`continue`** 是"跳过后面的语句，直接进入下一轮"——小心它可能跳过你本该执行的更新逻辑。
7. **循环变量用 `uint8_t` 却写 `i >= 0`** → 无符号数永远 `>= 0`，死循环。
8. **在 `for` 里修改数组长度相关的变量** → 循环次数不可预期。
