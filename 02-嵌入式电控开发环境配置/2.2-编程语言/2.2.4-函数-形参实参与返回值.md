# 2.2.4 函数、形参、实参、返回类型

> **一句话本质：函数 = 输入（形参）→ 处理 → 输出（返回值）。**
> 它是把"一段逻辑"起个名字，让主流程读起来像一句话。

---

## 一、三个词，一次讲清

```c
int16_t Limit(int16_t v, int16_t min, int16_t max)   // ← 形参：v, min, max
{
    if (v < min) return min;
    if (v > max) return max;
    return v;
}

int main(void)
{
    int16_t out = Limit(2000, -1000, 1000);          // ← 实参：2000, -1000, 1000
    return 0;
}
```

| 术语 | 是什么 | 类比 |
|---|---|---|
| **形参** | 定义函数时写的变量名，是**占位符** | 报表上的空格 |
| **实参** | 调用时真正传进去的值 | 你填进去的数字 |
| **返回类型** | 函数"吐"出来的东西的类型；不吐就写 `void` | —— |

一个函数**只能有一个返回值**。想返回多个结果 → 用指针（2.2.9）或结构体（2.2.5）。

---

## 二、核心机制：形参是"复印件"

这一点必须刻进脑子，否则 bug 会一直找你：

```c
void TryChange(int16_t v)
{
    v = 999;          // 改的是"复印件"
}

int main(void)
{
    int16_t speed = 100;
    TryChange(speed);
    printf("%d\n", speed);   // 输出 100，不是 999
}
```

调用那一刻，实参的值被**拷贝**一份给形参。函数里怎么改，改的都是那份拷贝，外面的变量纹丝不动。

**想让函数改外面的变量怎么办？** 传"地址"而不是"值"——这就是指针存在的头号理由（见 2.2.9）。

## 三、队里长什么样

```c
/* chassis.c */
static int16_t LimitSpeed(int16_t v)          /* 本文件内部用 → static，见 2.2.8 */
{
    const int16_t MAX = 1000;
    if (v >  MAX) return  MAX;
    if (v < -MAX) return -MAX;
    return v;
}

/* 输入：目标与实际；输出：4 个轮子的输出值（通过数组返回） */
void Chassis_Calc(int16_t target[], int16_t actual[], int16_t out[], uint8_t num)
{
    for (uint8_t i = 0; i < num; i++) {
        out[i] = LimitSpeed(target[i] - actual[i]);
    }
}
```

好函数的样子：

- **短**：一件事。需要滚动三屏才能看完的函数，几乎一定有 bug 藏着。
- **名字即文档**：`Chassis_Calc` 比 `doit` 强一万倍。
- **参数少**：超过 4~5 个参数就该考虑"打包成结构体"传进去。

## 四、常见坑

1. **有返回类型却忘了 `return`**
   → 编译器可能只给个警告，运行结果随机。
2. **调用时实参顺序写反**：`Limit(1000, 2000, -1000)` 逻辑直接崩，编译器不会拦你。
   （参数语义不清时，宁可传结构体。）
3. **在 `.h` 里写函数体** → 重复定义（见 2.2.2）。
4. **改了形参以为改了外面** → 上面那条"复印件"规则。
5. **数组作参数，`sizeof` 拿不到元素个数**
   → 必须额外传一个 `num` 参数（数组做参数时会"退化"成指针，2.2.9 细说）。
