# 2.2.9 进阶 · 指针

> **一句话本质：指针就是一个保存"地址"的变量。**
> 普通变量里装数据，指针里装"数据在哪"。

---

## 一、类比：门牌号

- 你要搬走家具，**手里抄的纸条上写的不是家具，是门牌号**。
- 按门牌号找过去，才能进屋子搬东西。

```c
int16_t  speed = 100;      /* 数据本身（屋里的家具） */
int16_t *p     = &speed;   /* 指针（写着门牌号的纸条） */
```

| 符号 | 读作 | 干什么 |
|---|---|---|
| `&speed` | 取地址 | 得到 `speed` 的门牌号 |
| `int16_t *p` | 指针变量 | 声明"p 里存的是地址" |
| `*p` | 解引用 | 按 p 里的地址找过去，**操作屋里的东西** |

```c
*p = 500;        /* 找到 speed，把它改成 500（speed 真的变成 500 了） */
int16_t v = *p;  /* 把屋里的值取出来 */
```

---

## 二、为什么嵌入式躲不开指针

| 场景 | 原因 |
|---|---|
| 让函数改外部变量 | 形参只是"复印件"（2.2.4），想改原件就得传地址 |
| 数组 / 字符串 | 数组名本身就代表首元素地址，本质是同一套东西 |
| 访问硬件寄存器 | 寄存器就是"固定地址的内存"，只能用指针去读写（2.2.1 那行"魔法"） |
| 厂商库函数 | `HAL_UART_Transmit(&huart1, ...)`、`HAL_ADC_Start(&hadc1)`——**参数里全是 `&`** |
| 大结构体传参 | 传地址 = 只传 4 个字节，而不是把整个结构体复制一份 |

**所以：看不懂 `&` 和 `*`，你就看不懂 HAL 库的任何一个函数调用。**

## 三、指针的四个常用姿势

### 1. 在函数里改外部变量（头号用途）

```c
void SetSpeed(int16_t *target)
{
    *target = 500;              /* 改的是外面那个变量的本体 */
}

int main(void)
{
    int16_t speed = 0;
    SetSpeed(&speed);           /* 传地址进去 */
    /* 此时 speed == 500 */
}
```

### 2. 数组名就是指针

```c
int16_t chassis[4];

chassis      /* 等价于 &chassis[0]，是首元素的地址 */
chassis[2]   /* 等价于 *(chassis + 2) */
```

这也解释了**为什么数组下标从 0 开始**：`*(chassis + 0)` 就是第一个元素。

> 由此推论：数组当参数传给函数时，传的是**首地址**，函数拿不到"数组有多长"——
> 所以必须**额外传一个 `num`**（对应 2.2.4 的坑）。

```c
void PrintAll(int16_t arr[], uint8_t num)   /* 这里的 arr[] 就是一个指针 */
{
    for (uint8_t i = 0; i < num; i++) {
        printf("%d ", arr[i]);
    }
}
```

### 3. 结构体指针用 `->`

```c
void PID_Reset(PID_t *pid)
{
    pid->kp = 0;        /* 等价于 (*pid).kp = 0，箭头更好读 */
    pid->ki = 0;
    pid->kd = 0;
}

PID_Reset(&chassis.pid[0]);
```

### 4. 访问寄存器（呼应 2.2.1）

```c
#define GPIOB_ODR   (*(volatile uint32_t *)0x40020414)   /* 把地址"变成"一个可读写的变量 */

GPIOB_ODR |= (1 << 8);      /* 把 PB8 置高，不影响其它位 */
GPIOB_ODR &= ~(1 << 8);     /* 把 PB8 拉低 */
```

拆开读这句话：

- `(uint32_t *)0x40020414`：把数字当成"指向 32 位数据的地址"
- 前面那个 `*`：解引用，于是 `GPIOB_ODR` 就"长得像"一个普通变量
- `volatile`：告诉编译器"每次都要真的去读写"（见 2.2.8）

**这就是从"人类语言"到"寄存器操作"的完整链条**——HAL 库函数内部做的也是这件事，只是帮你包了一层。

## 四、危险与规矩

指针是 C 的一把快刀，割手的三种方式：

1. **空指针**：`int16_t *p = NULL; *p = 1;` → 直接跑飞（HardFault）。
2. **野指针**：指针没初始化就解引用，指向一个随机地址 → 症状完全随机。
3. **悬空指针**：指向已经"不存在"的东西
   ```c
   int16_t *Bad(void)
   {
       int16_t local = 5;
       return &local;      /* 错！函数一返回，local 就没了 */
   }
   ```
4. **越界**：指针加减超出数组范围，C 不会拦你。

### 四条保命规矩

1. **定义时就赋值**：`int16_t *p = &speed;` 或 `= NULL;`，绝不留空。
2. **函数参数是指针时，先判断**：`if (pid == NULL) return;`
3. **绝不返回局部变量的地址。**
4. **谁分配的内存谁负责**（嵌入式里尽量不用 `malloc`，静态分配最安全）。
