# 2.2.1 为什么用 C 语言

> **一句话本质：C 离硬件最近。**
> 你写下的意图，和芯片真正执行的动作之间，几乎没有中间层。

---

## 一、先看一件"别的语言做不到"的事

下面这行代码，把 `0x00000100` 写进了内存地址 `0x40020414`：

```c
*(volatile uint32_t *)0x40020414 = 0x00000100;   // 让 PB8 输出高电平（前提：PB8 已配成输出模式）
```

而 `0x40020414` 这个地址，正是芯片里"控制 PB8 引脚电平"的那个**寄存器**。
**写内存 = 控制引脚。** 这就是嵌入式最底层的真相。

Python / Java 写不出这一句——它们不允许你直接碰地址。

> 这行代码现在看不懂完全正常，2.2.9 讲完指针你就懂了。这里只是让你先看一眼 C 能干什么。
> （不同 STM32 系列这个地址不一样，所以要靠"宏 / 库函数"而不是背地址——见 2.2.8。）

---

## 二、C 凭什么统治嵌入式

| C 的特点 | 对机器人意味着什么 |
|---|---|
| 能直接读写内存地址 | 芯片的寄存器本质就是"固定地址的内存" |
| 编译成机器码，没有"运行时" | 没有垃圾回收突然卡一下，控制周期稳定、可预测 |
| 代码体积、执行时间可控 | 几十 KB RAM 的单片机也跑得动 |
| 库和例程最多 | 厂商手册示例、HAL 库、开源飞控/机器人代码基本都是 C |
| 可移植 | 换芯片、换板子，改动通常很小 |

> 反过来说：**C++、Python、Rust 也能写机器人**，只是队里的历史代码、库函数、调试手段全是 C。
> 学 C 不是因为它"高级"，而是因为它是这个圈子的**通用货币**——谁都认识。

---

## 三、代价：它不会替你兜底

C 把控制权交给你，也把责任交给你：

- 它**不检查数组越界**——写下标 4 改的是别人的内存。
- 它**不管内存**——指针指错，程序当场"跑飞"（HardFault）。
- 报错很原始——经常只有一句 `HardFault_Handler` 或者串口里一行乱码。

这就是队里为什么反复强调**规范**：命名、分层、头文件边界，都是在替 C 补上它不给的安全网。

---

## 四、你真正要学的不是语法

C 的语法一周就能看完，决定水平的从来是下面三件事：

1. **这段代码在芯片里变成了什么？** → 编译流程，见 2.2.7
2. **数据在内存里长什么样？** → 数组 / 结构体 / 对齐，见 2.2.3、2.2.5
3. **出错了怎么定位？** → 调试器、示波器、串口打印
