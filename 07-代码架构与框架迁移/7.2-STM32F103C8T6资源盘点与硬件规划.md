# 7.2 · STM32F103C8T6 资源盘点与硬件规划

> 需求清单上的每一条，最后都要落到**一根引脚、一个外设**上。
> 落不下去，不是芯片不行，是你还没算过账。

## 这一节在干什么

拿 7.1 的需求清单，盘点 STM32F103C8T6 的资源，产出一张**外设 / 引脚分配表**。

做完你会知道：哪路定时器出 PWM、哪个串口接蓝牙、IMU 挂在哪条总线、还剩多少余量。

## 先认清你手上这块芯片

| 项目 | STM32F103C8T6 |
|---|---|
| 内核 / 主频 | Cortex-M3 / 72 MHz |
| Flash | 64 KB |
| **RAM** | **20 KB** ← 最容易被忽略的瓶颈 |
| 封装 / 可用 IO | LQFP48 / 37 个 |
| 串口 | 3 个 USART |
| 定时器 | 4 个（TIM1 高级 + TIM2/3/4 通用），每个 4 通道 |
| 其他 | 2×SPI、2×I2C、2×12 位 ADC、USB、CAN |

> 💡 20 KB RAM 是什么概念：光是一个千点的浮点缓冲就吃掉一大块。
> 后面用不用 RTOS、帧缓冲开多大，都得先看这个数。

## 第一步：需求 → 资源清单

把 7.1 的需求逐条翻译成"需要什么硬件资源"：

| 需求 | 需要的资源 | 数量 |
|---|---|---|
| 底盘四个轮子调速 | 定时器 PWM（一路一个通道） | 4 路 |
| 机械臂多个舵机 | 定时器 PWM，50 Hz | 每舵机 1 路 |
| 接收遥控指令 | USART + 中断或 DMA | 1 路 |
| 读取姿态（IMU） | I2C 或 SPI | 1 路 |
| 轮速反馈（闭环） | 定时器编码器模式 | 每轮 1 个定时器 |
| 打印调试 | USART | 1 路 |

> 先写满，再去抢资源。**别一边写一边安慰自己"应该够用"。**

## 第二步：算账，找出冲突

对着上面那张表点一遍手上的定时器，你会撞上这种事（示范）：

```
4 个电机 PWM   → 占 TIM3 的 4 个通道
机械臂舵机 PWM → 占 TIM4
IMU + 蓝牙     → 不占定时器
4 个编码器     → 需要 4 个定时器，但只剩 TIM1、TIM2
                  ↑ 不够了
```

**发现冲突，是这一节最有价值的时刻。**资源不够时按顺序做三件事：

1. **先看需求能不能让步** —— 四个轮子都需要编码器吗？只测两个行不行？
2. **再看有没有替代实现** —— 编码器能不能用外部中断计数？（代价是占 CPU、高速时丢脉冲）
3. **最后才考虑换芯片** —— 需求确实要求，就带着"差多少"去和组长谈

> ⚠️ 第三步以前，先把前两步的结论写清楚。
> "芯片不行"这句话，只有在算过账之后才有资格说。

## 第三步：把引脚钉死，并留出余量

分配引脚时守住三条：

1. **调试口不能动** —— PA13/PA14（SWD）一关，你就再也没有调试器了。
2. **复用功能别打架** —— 一个引脚只能干一件事，TIM、USART、I2C 都要抢。
3. **留余量** —— 至少留几路空闲 IO 和一路备用串口。赛场上临时加个蜂鸣器、加个开关，不至于推翻整张表。

分配表模板：

| 外设 | 用途 | 引脚 | 模式 / 参数 | 备注 |
|---|---|---|---|---|
| TIM3_CH1 | 底盘左前电机 | PA6 | PWM，频率待定 |  |
| USART1 | 蓝牙遥控 | PA9 / PA10 | 115200，中断接收 |  |
| I2C1 | IMU | PB6 / PB7 | 400 kHz |  |
|  |  |  |  |  |

> 频率、波特率这些参数，在 7.4 用 CubeMX 配置时再定死。
> 现在只要保证**谁占什么、够不够、有没有冲突**是清楚的。

## 交付物

1. **外设 / 引脚分配表** —— 每个外设对应哪个需求、哪根引脚
2. **资源余量表** —— 定时器 / 串口 / IO / RAM 还剩多少
3. **冲突与取舍说明** —— 撞了什么、砍了什么、为什么这么砍

## 验收标准

- [ ] 分配表上每一条，都能指回 7.1 的某条需求
- [ ] 能说出至少一处资源冲突，以及你怎么取舍的
- [ ] SWD 调试口没被动过
- [ ] 现场提问：把电机从 4 个改成 6 个，你要动哪里？还够吗？
