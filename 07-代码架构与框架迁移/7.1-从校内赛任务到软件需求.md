# 7.1 · 拿到赛题的第一件事：把需求想清楚

> 校内赛所有的代码，都是从这一页纸开始的。
> 需求没想清楚，后面每一层都要返工。

## 这一章我们在干什么

带着你，拿校内赛的真实任务，从零走一遍一个项目：

```
需求分析 → 选硬件 → 决定程序怎么跑 → 分层写代码 → 通信用协议 → 整机联调 → 换芯片、换传感器
```

每一步都问同一个问题：**这块东西，以后会被谁用到？**

校内赛要做的两件事（出自 `06-校内赛引言/校内赛的任务分析.pdf`）：

```
底盘   ：目标速度 → 运动学解算     → 4 个轮速 → 电机
机械臂 ：目标位姿 → 逆运动学解算   → 各个角度 → 舵机
```

两条链长得一模一样，都是 **输入数据 → 解算 → 输出数据 → 执行器**。
所以先拿底盘这一条链把需求分析讲透，机械臂那条照搬。

## 为什么第一步不是打开 CubeMX

新手最容易跳过的就是这一步：拿到题，直接点引脚、写 `while(1)`。然后：

- 做到一半发现定时器不够用，只好推倒重来
- 遥控协议改了一个字节，控制代码跟着大改
- 该停车的时候，没人说得清"什么样的条件算该停车"

**这些返工不是意外，是必然。** 需求分析不是交作业，是**把后面要做的决定提前想一遍**。

> ⚠️ 需求分析和"看懂了赛题"是两回事。
> "看懂"是你脑子里觉得明白了；"需求分析"是写下来、能被人检查、能拿去选硬件的东西。

## 怎么问：顺着数据流一路问下去

### 第一步：把"人话"翻译成"机器话"

赛题说"按预定轨迹运动""让末端到指定位置"，对人是一句话，对程序什么都不是。
把它拆成机器能回答的问题：

| 要问的 | 底盘的答案（示范） | 你的项目填什么 |
|---|---|---|
| 机器接收什么输入？ | 遥控端发来的目标速度 `vx`、`vy`、`ω` |  |
| 是什么类型？多大范围？ | 浮点数 / 正负都有 / 上限待定 |  |
| 多久来一次？ | 周期性下发，周期待定 |  |
| 谁决定的？ | 遥控端（人） |  |

> 填不出来不是丢人，是**你确实还不知道**。
> 写进"待确认清单"，找组长问 —— 但不能假装它不重要。

### 第二步：把输入一步步推到输出，每个箭头都问三句话

底盘这条链：

```
蓝牙帧 → 解包校验 → 目标速度 → 运动学解算 → 限幅 → 4 个占空比 → 电机
```

每经过一个箭头，问三句话：

1. **这一步进什么、出什么？** —— 比如解包：进的是字节流，出的是 `vx/vy/ω`
2. **出错了怎么办？** —— 校验不过呢？算出来超出电机能力呢？
3. **这个量多久更新一次、最晚多久得响应？**

> 这三句话的答案，就是你需求清单的原始素材。

### 第三步：功能和"出事的时候"一起写

新手只写功能需求（"车能走"），漏掉下面这些，赛场上就出事：

| 类别 | 底盘上的例子 | 不写会怎样 |
|---|---|---|
| 时序 | 蓝牙断连 500 ms 内必须停车 | 车失控冲出去 |
| 范围 / 限幅 | 解算出的轮速超上限时，整体等比缩放 | 每轮各自削顶，转弯轨迹变形 |
| 异常 | IMU 读不到数据怎么办 —— 拒绝启动还是降级运行？ | 上电就疯跑 |
| 边界 | 机械臂目标点太远，逆运动学解不出来 | 舵机乱转、卡死 |

**"出错的时候怎么办"和"正常的时候怎么办"一样重要。**
这不是额外的要求，这就是需求本身。

### 第四步：写清怎么证明它做到了

写不出验收方法的需求，其实是一句口号，不是需求。

| ID | 需求 | 验收方法 |
|---|---|---|
| REQ-F-01 | 收到有效蓝牙帧后，底盘应解算出四个轮子的目标转速 | 发一组 `vx/vy/ω`，看四个轮子转向、转速比例是否正确 |
| REQ-T-01 | 蓝牙断连后 500 ms 内，电机停止输出 | 现场拔掉蓝牙，看车是否停住并计时 |
| REQ-S-01 | 解算结果超出电机能力时，应整体等比缩放而不是各自削顶 | 给一个超量程目标，观察四个轮速是否保持比例 |

> 编号（`F` 功能 / `T` 时序 / `S` 安全）以后会一直用：
> 连接硬件清单、连接代码模块、连接测试记录。**一条需求从赛题走到验收，全程可追溯。**

## 交付物

1. **需求清单** —— 功能 / 时序 / 范围 / 异常 / 安全，每条都有 ID 和验收方法
2. **数据流图** —— 从输入画到执行器，标出每一步在哪儿执行（中断？主循环？定时器？）
3. **待确认清单** —— 还不知道的，写清要问谁、问什么

## 验收标准

- [ ] 随机抽一条需求，能说出它来自赛题哪句话、以后会影响哪一层
- [ ] 数据流图上每个箭头的输入输出都说得出
- [ ] 至少 2 条"出错怎么办"的需求，且能现场验证
- [ ] 待确认清单有人负责跟进

> 这一节的产出，下一节直接变成硬件资源清单：要几路 PWM？几路串口？用不用定时器？
> **需求不清，硬件选型就是拍脑袋。**
