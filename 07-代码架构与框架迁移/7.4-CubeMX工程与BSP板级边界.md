# 7.4 · CubeMX 工程与 BSP：把板级差异关在边界内

> CubeMX 给你的是"能跑的起点"，不是"能维护的工程"。
> 这一节要做的，就是在这两者之间画一条线。

## 这一节在干什么

按 7.2 的分配表，用 CubeMX 配出工程、验证外设，然后把"板子上有什么、接在哪根脚"收口到 BSP。

做完你会知道：**为什么换一块板子，不该动到你的控制算法。**

## 第一步：照着分配表配置，别自由发挥

打开 CubeMX 前，把 7.2 的表放在旁边。配置顺序：

1. **选芯片 / 封装** —— STM32F103C8Tx
2. **时钟** —— HSE 接外部晶振，PLL 倍频到 72 MHz，然后在时钟树里核对一遍
3. **调试口** —— SWD（PA13/PA14）**必须保留**，关掉就再也连不上调试器
4. **逐个外设** —— 每配一个，对照 7.3 的时序问一句："它在哪一层干活？"
   - PWM：频率、占空比初值
   - USART：波特率、**打开接收中断**
   - I2C：速率
5. **生成** —— 选好工具链，生成工程

> ⚠️ 配错一个复用功能，现象可能是"串口完全没反应"。
> 别急着怀疑硬件，先回来看引脚是不是被别的外设占了。

## 第二步：生成完先别写业务，先验证

新手最常见的错误是：生成完立刻开始堆功能，堆完发现"啥也不动"，然后无从下手。

**正确顺序是自底向上，一个外设一次：**

| 顺序 | 验证什么 | 怎么算过 |
|---|---|---|
| 1 | 程序能烧进去、能运行 | LED 闪烁 / 串口打印一句话 |
| 2 | 串口能收能发 | 发什么回来什么（回环） |
| 3 | PWM 能出波形 | 示波器看波形，或接上舵机/电机看它动 |
| 4 | 总线能通 | 读 IMU 的 ID，读到的值和手册一致 |

> 这个顺序和 `06-校内赛引言/校内赛前置任务.md` 的「单个外设 → 单条链路」是一回事：
> **一次只让一个东西可控，出了问题才知道是谁的问题。**

## 第三步：划清三层边界

| 层 | 谁生成的 | 能不能手改 | 放什么 |
|---|---|---|---|
| `Core/`、`Drivers/` | CubeMX | ❌ 会被覆盖 | 初始化、HAL 库 |
| `BSP/` | 你自己 | ✅ | 板级引脚、外设句柄、初始化封装 |
| `App/`、`Control/`、`Comm/` | 你自己 | ✅ | 业务逻辑、算法、通信 |

CubeMX 生成的代码里，只有 `USER CODE BEGIN/END` 之间是留给你写的。**其余地方改了，下次重新生成就没了。**

## 第四步：BSP 到底解决什么问题

对比一下两段写法：

```
// ❌ 上层直接碰 HAL：引脚写死在业务代码里
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_6, GPIO_PIN_SET);

// ✅ 上层只说要什么
BSP_Motor_SetDuty(MOTOR_LF, 0.6f);
```

第一种写法，将来电机从 PA6 挪到 PB0，你得**全项目搜 `GPIO_PIN_6`**，还得担心搜漏了。
第二种写法，只改 `bsp_motor.c` 里的一行映射。

> 这就是"边界"的全部意义：
> **把"会变的东西"集中在少数几个文件里，让其余代码不受影响。**

BSP 提供什么（示范）：

| 接口 | 作用 |
|---|---|
| `BSP_Init()` | 统一初始化板级外设 |
| `BSP_Motor_SetDuty(id, duty)` | 设某个电机占空比 |
| `BSP_Servo_SetAngle(id, deg)` | 设某个舵机角度 |
| `BSP_Uart_Write(buf, len)` | 往外发数据 |

> 注意接口里出现的都是**"电机""舵机""角度"**这些概念，
> 没有 `TIM3`、`HAL`、`GPIO_PIN_x` —— 那些是本层的私事，不外露。
